# 异常处理

异常会中断当前执行流程，并沿调用栈向外传播；找到匹配的处理器后执行处理代码，否则成为未处理异常。

- `SyntaxError`：解析代码时发现语法错误，不能通过同一代码块中的 `try` 捕获；导入模块或调用 `compile()` 时产生的语法错误可以捕获。
- 运行时异常：例如除零、类型不匹配、文件不存在等，可以按异常类型处理。
- 阅读 `Traceback` 时，先看末尾的异常类型和错误信息，再沿调用栈定位自己的代码。

# `try...except`

```text
try:
    可能引发异常的代码
except 异常类型 as exc:
    异常处理代码
else:
    try 正常执行完毕后执行
finally:
    离开 try 语句前执行清理
```

`except` 可以有多个，`else` 和 `finally` 可省略；`try` 至少需要搭配 `except` 或 `finally`。

```python
try:
    number = int("abc")
except ValueError as exc:
    print(f"转换失败：{exc}")
```

异常发生后，`try` 中剩余的代码不会继续执行；异常处理结束后，从整个 `try` 语句后继续执行，不会返回出错的位置重试。

# 异常触发流程

`try` 也能捕获其内部调用的函数抛出的异常，包括间接调用：

```python
def parse_number(text):
    return int(text)


try:
    parse_number("abc")
except ValueError:
    print("请输入有效的整数")
```

当前层无法处理时，异常继续传给调用者；通常在能够恢复、转换错误或统一报告的位置处理即可。

# 常见异常类型

| 异常类型 | 常见原因 |
| --- | --- |
| `TypeError` | 对象类型不适合该操作，例如 `"1" + 1` |
| `ValueError` | 类型合适但值不合法，例如 `int("abc")` |
| `NameError` | 使用未定义的名称 |
| `UnboundLocalError` | 在局部变量绑定前读取它，是 `NameError` 的子类 |
| `AttributeError` | 访问不存在的属性 |
| `IndexError` | 序列索引越界 |
| `KeyError` | 字典键不存在 |
| `ZeroDivisionError` | 除数为零 |
| `OSError` | 操作系统或输入输出错误 |
| `FileNotFoundError` | 文件或目录不存在，是 `OSError` 的子类 |
| `PermissionError` | 权限不足，是 `OSError` 的子类 |
| `ModuleNotFoundError` | 找不到导入的模块，是 `ImportError` 的子类 |
| `AssertionError` | `assert` 条件不成立 |

`Exception` 是常规异常的基类；`BaseException` 是所有异常的基类。`KeyboardInterrupt`、`SystemExit` 不属于 `Exception`，通常应允许它们继续传播。

# 捕获指定异常

## 匹配规则

- `except` 按从上到下的顺序匹配，普通 `try...except` 只执行第一个匹配的分支。
- 捕获某个异常类，也会捕获其子类；因此具体异常应写在基类之前。
- 多种异常采用相同处理方式时，可以写成元组。
- 同级 `except` 不会捕获其他 `except` 或 `else` 中新产生的异常，这些异常会向外传播。

```python
try:
    number = int(None)
except (TypeError, ValueError) as exc:
    print(f"无效的数字：{exc}")
```

Python 3.14 起，不使用 `as` 时可省略多异常类型外层的圆括号；保留括号仍然有效，且兼容旧版本。

## 异常对象与捕获范围

`as exc` 将异常实例绑定到变量，可读取 `str(exc)` 获取说明，或通过 `exc.args` 获取构造参数。该名称在 `except` 结束后会被清除，不应在块外继续使用。

尽量捕获明确的异常类型，并缩小 `try` 的范围。`except Exception` 适合在统一入口记录或处理未预期错误；裸 `except:` 还会捕获退出和中断异常，不宜用于普通业务处理。

# `else` 和 `finally`

## `else`

`else` 只在 `try` 正常执行到末尾时执行；发生异常或通过 `return`、`break`、`continue` 提前离开时，不执行 `else`。

```python
try:
    number = int("42")
except ValueError:
    print("转换失败")
else:
    print(number * 2)  # 84
```

成功后的操作放在 `else`，可避免其异常被前面的 `except` 意外捕获。

## `finally`

`finally` 用于清理：无论正常完成、发生异常，还是执行 `return`、`break`、`continue` 离开，都会先执行它。

```python
def get_value():
    try:
        return 42
    finally:
        print("执行清理")


print(get_value())
# 执行清理
# 42
```

以下流程假设处理与清理代码没有再次抛出异常或改变控制流：

| 情况 | 执行顺序 |
| --- | --- |
| `try` 正常执行到末尾 | `try` → `else`（若有）→ `finally`（若有） |
| 异常被捕获 | `try` → 匹配的 `except` → `finally`（若有） |
| 异常未被捕获 | `try` → `finally`（若有）→ 异常向外传播 |
| `try` 中执行 `return` | 计算返回值 → `finally`（若有）→ 返回 |

> **注意**：不要在 `finally` 中用 `return`、`break`、`continue` 跳出清理块，这可能覆盖返回值或丢弃待传播的异常；Python 3.14 起会对此发出 `SyntaxWarning`。`finally` 自身抛出异常时，新异常会继续传播，原异常成为其上下文。

# 主动抛出异常

## `raise`

使用 `raise 异常类型("说明")` 报告调用者需要处理的错误：

```python
def validate_age(age):
    if age < 0:
        raise ValueError("年龄不能为负数")
    return age
```

类型不合适通常抛出 `TypeError`；类型合适但值不合法通常抛出 `ValueError`。

## 重新抛出

处理异常时，不带参数的 `raise` 会继续抛出当前异常，保留原有回溯。没有正在处理的异常时，裸 `raise` 会引发 `RuntimeError`。

```python
import logging

try:
    int("abc")
except ValueError:
    logging.exception("数字解析失败")
    raise
```

`logging.exception()` 在异常处理块中记录错误说明及回溯；只打印 `exc` 不会输出完整调用栈。

## 异常链

将底层错误转换为更易理解的接口错误时，使用 `raise 新异常 from exc` 明确记录原因：

```python
def parse_port(text):
    try:
        return int(text)
    except ValueError as exc:
        raise ValueError("端口必须是整数文本") from exc
```

- `raise ... from exc`：将 `exc` 设为新异常的显式原因。
- 在 `except` 内直接抛出新异常：自动关联原异常作为上下文。
- `raise ... from None`：隐藏默认回溯中原异常的展示，原上下文仍然保留。

# 自定义异常

业务异常通常继承 `Exception` 或合适的具体异常类，名称以 `Error` 结尾。只需要区分异常类型时，类体使用 `pass` 即可。

```python
class PasswordTooShortError(ValueError):
    pass


def validate_password(password):
    if len(password) < 8:
        raise PasswordTooShortError("密码长度不能少于 8 位")


try:
    validate_password("123456")
except PasswordTooShortError as exc:
    print(exc)  # 密码长度不能少于 8 位
```

# 资源清理

文件、锁等支持上下文管理器的资源，优先使用 `with` 管理：

```python
with open("notes.txt", encoding="utf-8") as file:
    content = file.read()
```

文件成功打开后，无论读取是否抛出异常，离开 `with` 时都会关闭。资源清理与异常处理是两件事：这里的 `with` 不会自动吞掉读取异常，需要时在外层搭配 `try...except`。

# 断言

`assert 条件, "说明"` 用于检查程序内部假设；条件为假时抛出 `AssertionError`。

```python
count = 3
assert count >= 0, "内部计数不应为负数"
```

使用 `python -O` 时断言会被移除，因此输入校验和业务规则应使用 `if` 配合 `raise`。

# 异常组（了解）

Python 3.11 起，`ExceptionGroup` 可以将多个异常一起抛出，`except*` 按类型处理其中的子异常，常见于并发任务。

```python
try:
    raise ExceptionGroup("批量处理失败", [ValueError("数据无效"), TypeError("类型错误")])
except* ValueError as group:
    print(len(group.exceptions))  # 1
except* TypeError as group:
    print(len(group.exceptions))  # 1
```

多个 `except*` 分支可以分别执行，未处理的部分继续向外传播。同一个 `try` 不能混用 `except` 和 `except*`。
