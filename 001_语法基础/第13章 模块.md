# 模块

## 定义

一个 `.py` 文件通常就是一个模块，可以包含函数、类、变量和可执行语句。每个模块有自己的命名空间，模块内的全局变量不会自动进入导入方的作用域。

模块不一定是 `.py` 文件，也可以由解释器内置或通过 C 等语言实现。

## 模块分类

| 分类 | 说明 | 示例 |
| --- | --- | --- |
| 标准库模块 | 随 Python 提供，通常无需额外安装 | `math`、`json`、`pathlib` |
| 第三方模块 | 安装到当前 Python 环境后使用 | `requests` |
| 自定义模块 | 项目中编写的模块 | `calculator.py` |

### 第三方模块

在终端中安装，再在代码中导入：

```shell
python -m pip install requests
```

`python -m pip` 使用当前解释器对应的 pip；应先激活项目虚拟环境。安装时使用的发行包名与 `import` 名称不一定相同，具体以该项目文档为准。

环境和依赖管理详见[Python 项目与依赖管理](<../003_高级应用/第01章 Python 项目与依赖管理.md>)。

### 自定义模块

模块名通常使用简短的小写名称，必要时用下划线分隔。避免命名为 `json.py`、`random.py` 等已有模块名，防止同名遮蔽。

创建 `calculator.py`：

```python
__all__ = ["VERSION", "add"]
VERSION = "1.0.0"


def add(a, b):
    return a + b
```

# 导入模块

导入语句通常放在文件开头。以下示例在与 `calculator.py` 同级的脚本或交互环境中执行。

## import 模块名 [as 别名]

导入模块对象，通过 `模块名.名称` 访问其属性：

```python
import calculator

print(calculator.VERSION)    # 1.0.0
print(calculator.add(1, 2))  # 3
```

使用 `as` 为当前作用域中的模块引用设置别名：

```python
import calculator as calc

print(calc.add(1, 2))  # 3
```

别名不会复制模块，也不会改变模块自身的名称。

## from 模块名 import 名称

将指定名称直接绑定到当前作用域，使用时不需要模块名前缀：

```python
from calculator import VERSION, add as plus

print(VERSION)     # 1.0.0
print(plus(1, 2))  # 3
```

`from` 仍然会加载模块，不是只执行其中某个函数的定义。它不会自动将模块名 `calculator` 绑定到当前作用域。

导入名称不会复制对象，也不是与模块属性持续同步的绑定：

```python
import calculator
from calculator import VERSION

calculator.VERSION = "2.0.0"
print(VERSION)             # 1.0.0
print(calculator.VERSION)  # 2.0.0
```

如果导入的是可变对象，原地修改仍可能被双方看到，规则与普通赋值相同。

## from 模块名 import * 与 `__all__`

- 定义了 `__all__`：导入其中列出的名称。
- 没有定义 `__all__`：导入模块命名空间中不以下划线 `_` 开头的名称。
- `__all__` 只控制星号导入，不限制显式导入或属性访问，也不是访问权限机制。

本章的 `calculator.__all__` 包含 `VERSION` 和 `add`，因此星号导入只引入这两个名称。实际代码优先显式导入，避免名称冲突和来源不明。

# 模块初始化与缓存

首次成功导入普通 Python 源码模块时，会执行它的顶层代码，并将模块对象缓存在 `sys.modules` 中。之后按相同名称再次导入，通常直接复用缓存，不会再次执行顶层代码。

- 导入时也会执行模块中的赋值、打印、其他导入及函数定义等顶层语句。
- 函数体只有调用时才执行；函数定义时求值的默认参数等仍会执行。
- 避免在导入阶段直接发起请求、读取用户输入或启动业务流程。

交互调试时，修改源码后再次 `import` 通常不会更新已加载的模块。最直接的方式是重启解释器；也可以使用：

```python
import importlib
import calculator

importlib.reload(calculator)
```

`reload()` 会重新执行模块代码，但不会自动更新其他位置通过 `from ... import ...` 保存的旧引用，不宜作为常规业务中的更新机制。

# 以主程序的形式执行

`__name__` 用于区分模块的执行方式：

| 执行方式 | `__name__` |
| --- | --- |
| 直接运行文件或通过 `python -m 模块名` 执行 | `"__main__"` |
| 被其他模块导入 | 模块的完整名称，如 `calculator`、`utils.calculator` |

在 `calculator.py` 末尾添加：

```python
def main():
    print(add(1, 2))


if __name__ == "__main__":
    main()
```

运行方式：

```shell
python calculator.py
python -m calculator
```

两种方式都输出 `3`。被导入时不会调用这里的 `main()`，但保护块之外的顶层代码仍会执行。

`-m` 后面使用可导入的模块名称，不带 `.py`；解释器按模块搜索路径定位并执行它。

# 包

包本身也是模块，用于组织模块和子包。把前面的 `calculator.py` 放入 `utils/`，形成以下结构：

```text
project/
├── main.py
└── utils/
    ├── __init__.py
    ├── __main__.py
    └── calculator.py
```

## 创建包

常规包包含 `__init__.py`，文件可以为空。首次导入包时会执行其中的代码，通常只放简洁的初始化或公共接口导出。

Python 还支持不含 `__init__.py` 的命名空间包，主要用于将同名包的内容分布在多个位置；普通项目通常采用常规包即可。

## 使用包

在项目根目录的 `main.py` 中导入：

```python
from utils import calculator

print(calculator.add(1, 2))  # 3
```

也可以使用 `import utils.calculator`，通过 `utils.calculator.add()` 访问；或使用 `from utils.calculator import add` 直接导入函数。

仅执行 `import utils` 不会自动导入所有子模块；导入子模块时，会先初始化其父包。

## 绝对导入与相对导入

- **绝对导入**：从顶层包名开始，例如 `from utils.calculator import add`。
- **相对导入**：以当前包为基准，`.` 表示当前包，`..` 表示上一级包，例如 `from .calculator import add`。

相对导入依赖包上下文，不能超出顶层包。直接运行包内文件时通常缺少该上下文；包含相对导入的模块应优先通过 `python -m 包名.模块名` 执行。

## `__main__.py`

包中的 `__main__.py` 是 `python -m 包名` 的入口。例如 `utils/__main__.py`：

```python
from .calculator import add

print(add(1, 2))
```

在项目根目录执行：

```shell
python -m utils
```

输出 `3`。`__init__.py` 负责包初始化，`__main__.py` 负责以程序方式执行包，两者用途不同。

## 包的 `__all__`

在 `utils/__init__.py` 中设置 `__all__ = ["calculator"]`，可指定星号导入时导入该子模块。没有 `__all__` 时，`from utils import *` 不会自动扫描并导入目录中的所有模块。

# 模块搜索路径

导入首先检查 `sys.modules` 缓存；未命中时，再交给导入机制查找。默认机制会查找内置模块、冻结模块，再通过路径查找器搜索模块。

顶层模块的路径搜索由 `sys.path` 控制。默认启动配置下，主要包含：

1. 直接运行脚本时的脚本所在目录；交互模式、`-c` 和 `-m` 通常使用当前工作目录。
2. `PYTHONPATH` 环境变量指定的目录（若配置）。
3. 标准库与扩展模块目录。
4. 当前环境中的 `site-packages` 等依赖目录。

包内子模块通过父包的 `__path__` 查找；不能把所有导入都理解为只搜索当前目录。

```python
import sys

print(sys.executable)  # 当前解释器路径
print(sys.path)        # 顶层模块搜索路径
```

同名文件可能遮蔽标准库或第三方模块。排查时先确认解释器、启动目录和导入来源，避免长期通过 `sys.path.append()` 修补项目结构。

# 字节码缓存

导入 Python 源码模块时，解释器通常会在 `__pycache__/` 下缓存 `.pyc` 字节码，并在后续加载时检查是否仍然有效。

缓存用于减少重复编译，不会让同一段代码的执行速度变快，也不等同于 `sys.modules` 中的模块对象缓存。通常无需提交到版本库。

# 常见导入问题

| 问题 | 优先检查 |
| --- | --- |
| `ModuleNotFoundError` | 是否安装到当前解释器环境、模块名是否正确、包所在目录是否可搜索；也可能是目标模块内部依赖缺失 |
| `ImportError: cannot import name ...` | 名称是否存在、版本是否匹配、是否发生循环导入 |
| 导入了错误的模块 | 是否存在同名文件；文件型模块可查看其 `__file__` 定位来源 |
| 相对导入提示没有已知父包 | 是否直接运行了包内文件，改用正确的 `python -m ...` 入口 |
| 修改源码后导入结果没变 | 是否复用了当前解释器中的已加载模块 |

循环导入指模块相互依赖，导入过程中可能访问到尚未完成初始化的模块。优先将公共依赖抽到独立模块；必要时可在函数内延迟导入，但应先理清依赖关系。
