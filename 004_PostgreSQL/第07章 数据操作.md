# 准备工作

本章使用一个简化的 `company` 表演示数据操作。

先在练习数据库中执行下面的建表语句，后续示例会复用这张表；

生产环境执行写操作前，应确认目标数据库、事务边界和备份策略。

```postgresql
-- 删除已有表
DROP TABLE IF EXISTS company;
-- 新建表
CREATE TABLE company (
   id INT PRIMARY KEY     NOT NULL,
   name           TEXT    NOT NULL,
   age            INT     NOT NULL,
   address        CHAR(50),
   salary         REAL
);
```

# 插入数据 INSERT INTO

`INSERT` 用于向表中新增一行或多行，也可以把查询结果插入目标表。显式列出列名时，`VALUES` 中的每行表达式按列清单从左到右对应，数量必须匹配；未列出的列使用默认值，没有默认值时使用`NULL`。如果该列声明了`NOT NULL`且没有默认值，插入会失败。

语法格式：

```postgresql
INSERT INTO <table_name> (column1, column2, ...columnN) 
VALUES 
	(value1, value2, ...valueN),
	(value1, value2, ...valueN),
	...
```

如果省略列名，值会按表的声明顺序对应列。这种写法依赖表结构，增加或调整列后容易出错，因此业务代码和迁移脚本通常应显式写出列名：

```postgresql
INSERT INTO <table_name>  VALUES (value1,value2,value3,...valueN);
```

**实例**

在 COMPANY 表中插入以下数据：

```postgresql
INSERT INTO COMPANY (id,name,age,address,salary) 
VALUES 
	(1, '张三', 32, '成都', 20000.00);
```

以下插入语句省略了`salary`列；由于该列没有默认值，插入后其值为`NULL`：

```shell
INSERT INTO COMPANY (id,name,age,address) 
VALUES 
	(2, '李四', 32, '自贡');
```

以下实例插入多行：

```postgresql
INSERT INTO COMPANY (id,name,age,address,salary) 
VALUES 
  (3, '赵二', 31, '乐山', 20000.00),
  (4, '王五', 33, '绵阳', 65000.00),
  (5, '刘七', 33, '宜宾', 85000.00);
```

除`VALUES`外，`INSERT`还支持`DEFAULT VALUES`、`INSERT ... SELECT`、`ON CONFLICT`和`RETURNING`。其中`RETURNING`可以直接取得新插入行，`ON CONFLICT`可在唯一约束冲突时选择忽略或更新。

[INSERT 参考 ↪](https://www.postgresql.org/docs/18/sql-insert.html)

使用`SELECT`语句查询表格数据：

```postgresql
postgres=# SELECT * FROM company;

----+------+-----+---------+--------
  1 | 张三 |  32 | 成都    |  20000
  2 | 李四 |  32 | 自贡    |       
  3 | 赵二 |  31 | 乐山    |  20000
  4 | 王五 |  33 | 绵阳    |  65000
  5 | 刘七 |  33 | 宜宾    |  85000
(5 行记录)
```

# 更新数据 UPDATE

[UPDATE 参考 ↪](https://www.postgresql.org/docs/18/sql-update.html)

`UPDATE`用于修改表中符合条件的现有行。`SET`右侧可以是常量、表达式或其他列的值；`WHERE`决定哪些行会被修改。

语法格式：

```postgresql
UPDATE <table_name>
SET column1 = value1, column2 = value2...., columnN = valueN
WHERE [condition];
```

- 可以同时更新一个或多个字段。
- `WHERE`可以使用能得到布尔结果的条件；省略`WHERE`会更新整张表。
- 执行结果中的`UPDATE n`表示实际更新的行数；需要取回更新后的值时可以使用`RETURNING`。

**实例**

1）将 id 为 2 的那条数据中的 salary 字段设置为 15000

```postgresql
postgres=# UPDATE company SET salary = 15000 WHERE id = 2;
UPDATE 1
```

得到结果如下：

```postgresql
 id | name | age | address | salary 
----+------+-----+---------+--------
  1 | 张三 |  32 | 成都    |  20000
  3 | 赵二 |  31 | 乐山    |  20000
  4 | 王五 |  33 | 绵阳    |  65000
  5 | 刘七 |  33 | 宜宾    |  85000
  2 | 李四 |  32 | 自贡    |  15000
```

2）同时更新 salary 字段和 address 字段的值：

```postgresql
postgres=# UPDATE company SET address = '未知', salary = 20000;
UPDATE 5
```

得到结果如下：

```postgresql
 id | name | age | address | salary 
----+------+-----+---------+--------
  1 | 张三 |  32 | 未知    |  20000
  3 | 赵二 |  31 | 未知    |  20000
  4 | 王五 |  33 | 未知    |  20000
  5 | 刘七 |  33 | 未知    |  20000
  2 | 李四 |  32 | 未知    |  20000
```

# 删除数据 DELETE

[DELETE 参考 ↪](https://www.postgresql.org/docs/18/sql-delete.html)

`DELETE`用于删除表中符合条件的行。它逐行处理删除操作，通常可以配合`WHERE`精确选择目标；需要保留表结构但一次清空全部数据时，可比较`TRUNCATE`的行为。

语法格式：

```postgresql
DELETE FROM <table_name> WHERE <condition>;
```

如果没有指定`WHERE`子句，表中的所有记录都会被删除。删除前应先用同样的条件执行`SELECT`确认范围，并在重要操作中使用事务；`DELETE ... RETURNING`可以返回被删除的行。

`WHERE`条件可以使用`AND`、`OR`和`NOT`组合多个判断；条件结果为`NULL`（未知）时不会选中该行。

**实例**

1）删除 id = 2 的记录：

```postgresql
postgres=# DELETE FROM company WHERE id = 2;
DELETE 1
```

2）删除所有记录：

```postgresql
postgres=# DELETE FROM company;
DELETE 4
```

## SELECT

[SELECT 参考 ↪](https://www.postgresql.org/docs/18/sql-select.html)

返回的行组成结果集；结果集是本次查询的输出，并不表示 PostgreSQL 会自动把它持久化为一张表。

语法格式：

```postgresql
SELECT column1, column2,...columnN FROM <table_name>;
```

## 运算符

[运算符与函数参考 ↪](https://www.postgresql.org/docs/18/functions.html)

运算符是表达式中的操作符，用于进行算术、比较、逻辑或位运算。具体结果由操作数的数据类型和运算符定义决定。

PostgreSQL 的运算符可以由符号或关键字组成，常见于`SELECT`列表和`WHERE`条件，也可以用于`UPDATE`等数据操作语句。

常见的运算符有：

- 算术运算符：`+` `-` `*` `/` `%` `!` ...
- 比较运算符：`>` `>=` `<` `<=` `=` `!=` ...
- 逻辑运算符：`AND` `NOT` `OR`
- 按位运算符：`&` `|` `#` `~` `<<` `>>`
- 幂运算符：`^`

涉及`NULL`时，普通比较通常得到未知结果，而不是`TRUE`或`FALSE`；判断空值应使用`IS NULL`或`IS NOT NULL`。

**实例**

1）**查询 name 和 age，然后 age 在原有基础上加 100**：

```postgresql
postgres=# SELECT name,age+100 FROM company;
 name | ?column? 
------+----------
 赵云 |      128
 吕布 |      130
 貂蝉 |      122
 李白 |      126
 韩信 |      124
 妲己 |      120
 孙策 |      125
 张良 |      135
 大乔 |      123
(9 行记录)
```

可以看到， age 列的值是没有问题的，但是列标题是 `?column?`，此时我们可以通过 `AS` 关键字给列标题赋值，如：

```postgresql
postgres=# SELECT name,age+100 AS new_age  FROM company;
 name | new_age 
------+---------
 赵云 |     128
 吕布 |     130
 貂蝉 |     122
 李白 |     126
 韩信 |     124
 妲己 |     120
 孙策 |     125
 张良 |     135
 大乔 |     123
(9 行记录)
```

2）**查询 age >= 25，同时 salary > 30000 的记录**：

```postgresql
postgres=# SELECT * FROM company WHERE age >= 25 AND salary > 30000;
 id | name | age | address | salary 
----+------+-----+---------+--------
  4 | 李白 |  26 | 碎叶    |  35000
  7 | 孙策 |  25 | 江东    |  32000
  8 | 张良 |  35 | 颍川    |  40000
(3 行记录)
```

## 表达式

[值表达式参考 ↪](https://www.postgresql.org/docs/18/sql-expressions.html)

表达式由常量、列引用、函数调用、运算符或子表达式组成，并计算出一个值和对应的数据类型。

表达式可以出现在`SELECT`列表、`WHERE`、`ORDER BY`、`GROUP BY`以及数据修改语句中，用于计算结果或筛选行。

SELECT 语句的语法格式如下：

```postgresql
SELECT column1, column2, columnN
FROM <table_name>
WHERE [CONDITION | EXPRESSION];
```

PostgreSQL 的表达式可以有不同类型：

- 布尔表达式
- 数字表达式
- 日期表达式

### 布尔表达式

布尔表达式会计算出`TRUE`、`FALSE`或`NULL`，常用于`WHERE`和`HAVING`中筛选数据：

```postgresql
SELECT column1, column2, columnN
FROM <table_name>
WHERE SINGLE VALUE MATCHTING EXPRESSION;
```

以下使用了布尔表达式（**SALARY=25000**）来查询数据：

```postgresql
postgres=# SELECT * FROM company WHERE salary = 25000;
 id | name | age | address | salary 
----+------+-----+---------+--------
  1 | 赵云 |  28 | 常山    |  25000
(1 行记录)
```

### 数字表达式

数字表达式常用于查询语句中的数学运算：

```postgresql
SELECT numerical_expression as  OPERATION_NAME
[FROM table_name WHERE CONDITION] ;
```

**numerical_expression** 是一个数学运算表达式，实例如下：

```postgresql
postgres=# SELECT (10 + 10) AS sum_result;
 sum_result 
------------
         20
(1 行记录)
```

此外 PostgreSQL 还内置了一些数学函数，如：

- `AVG()`：返回输入值的平均值，通常忽略`NULL`。
- `SUM()`：返回输入值的总和；没有非空输入时结果为`NULL`。
- `COUNT(*)`：返回行数；`COUNT(expression)`只统计表达式结果不为`NULL`的行。

1）以下实例查询 COMPANY 表的记录总数：

```postgresql
postgres=# SELECT COUNT(*) AS total_count FROM company;
 total_count 
-------------
           9
(1 行记录)
```

### 日期表达式

日期/时间表达式可以进行日期计算、截断和格式化。`CURRENT_TIMESTAMP`返回当前事务开始时的带时区时间；需要每次调用都读取实际时钟时，应了解`clock_timestamp()`的差异。以下实例查询当前时间：

```postgresql
postgres=# SELECT CURRENT_TIMESTAMP;
       current_timestamp       
-------------------------------
 2025-06-24 16:13:44.276889+08
(1 行记录)
```

## WHERE

[WHERE 子句参考 ↪](https://www.postgresql.org/docs/18/sql-select.html)

在 PostgreSQL 中，`WHERE`用于根据条件过滤行。它可以出现在`SELECT`、`UPDATE`和`DELETE`等语句中；连接多张表时，`WHERE`仍然是在`FROM`产生的行集上继续筛选。

条件表达式必须得到布尔结果。只有结果为`TRUE`的行会被保留；结果为`FALSE`或`NULL`（未知）的行都会被过滤掉。

以下是 SELECT 语句中使用 WHERE 子句从数据库中读取数据的通用语法：

```postgresql
SELECT column1, column2, columnN
FROM <table_name>
WHERE [condition1]
```

我们可以在`WHERE`中使用比较运算符、逻辑运算符、`LIKE`、`IN`、`BETWEEN`和子查询等条件。

以下示例分别演示逻辑运算、空值判断、模式匹配、集合判断、范围判断和子查询。

> **`AND`**

找出 **AGE(年龄)** 字段大于等于 25，并且 **SALARY(薪资)** 字段大于等于 35000 的数据：

```postgresql
postgres=# SELECT * FROM company WHERE age >= 25 AND salary >= 35000;
 id | name | age | address | salary 
----+------+-----+---------+--------
  4 | 李白 |  26 | 碎叶    |  35000
  8 | 张良 |  35 | 颍川    |  40000
(2 行记录)
```

> **`OR`**

找出 **AGE(年龄)** 字段大于等于 25，或者 **SALARY(薪资)** 字段大于等于 35000 的数据：

```postgresql
postgres=# SELECT * FROM company WHERE age >= 25 OR salary >= 35000;
 id | name | age | address | salary 
----+------+-----+---------+--------
  1 | 赵云 |  28 | 常山    |  25000
  2 | 吕布 |  30 | 洛阳    |  30000
  4 | 李白 |  26 | 碎叶    |  35000
  7 | 孙策 |  25 | 江东    |  32000
  8 | 张良 |  35 | 颍川    |  40000
(5 行记录)
```

> **`IS NOT NULL`**

在公司表中找出 **AGE(年龄)** 字段不为空的记录：

```postgresql
postgres=# SELECT * FROM company WHERE age IS NOT NULL;
 id | name | age | address | salary 
----+------+-----+---------+--------
  1 | 赵云 |  28 | 常山    |  25000
  2 | 吕布 |  30 | 洛阳    |  30000
  3 | 貂蝉 |  22 | 长安    |  18000
  4 | 李白 |  26 | 碎叶    |  35000
  5 | 韩信 |  24 | 淮阴    |  28000
  6 | 妲己 |  20 | 青丘    |  15000
  7 | 孙策 |  25 | 江东    |  32000
  8 | 张良 |  35 | 颍川    |  40000
  9 | 大乔 |  23 | 吴郡    |  22000
(9 行记录)
```

> **`LIKE`**

在 COMPANY 表中找出 **NAME(名字)** 字段中以 李 开头的数据：

```postgresql
postgres=# SELECT * FROM company WHERE name LIKE '李%';
 id | name | age | address | salary 
----+------+-----+---------+--------
  4 | 李白 |  26 | 碎叶    |  35000
(1 行记录)
```

> **`IN`**

以下 SELECT 语句列出了 **AGE(年龄)** 字段为 20 或 25 的数据：

```postgresql
postgres=# SELECT * FROM company WHERE age IN (20, 25);
 id | name | age | address | salary 
----+------+-----+---------+--------
  6 | 妲己 |  20 | 青丘    |  15000
  7 | 孙策 |  25 | 江东    |  32000
(2 行记录)
```

> **`NOT IN`**

以下 SELECT 语句列出了 **AGE(年龄)** 字段不为 20 或 25 的数据：

```postgresql
postgres=# SELECT * FROM company WHERE age NOT IN (20, 25);
 id | name | age | address | salary 
----+------+-----+---------+--------
  1 | 赵云 |  28 | 常山    |  25000
  2 | 吕布 |  30 | 洛阳    |  30000
  3 | 貂蝉 |  22 | 长安    |  18000
  4 | 李白 |  26 | 碎叶    |  35000
  5 | 韩信 |  24 | 淮阴    |  28000
  8 | 张良 |  35 | 颍川    |  40000
  9 | 大乔 |  23 | 吴郡    |  22000
(7 行记录)
```

使用`NOT IN`时要注意`NULL`：如果待比较列或列表中包含`NULL`，条件可能得到未知结果而不会选中该行。需要空值安全的排除逻辑时，可考虑使用`NOT EXISTS`。

> **`BETWEEN`**

以下 SELECT 语句列出了 **AGE(年龄)** 字段在 25 到 30 的数据：

```postgresql
postgres=# SELECT * FROM company WHERE age BETWEEN 25 AND 30;
 id | name | age | address | salary 
----+------+-----+---------+--------
  1 | 赵云 |  28 | 常山    |  25000
  2 | 吕布 |  30 | 洛阳    |  30000
  4 | 李白 |  26 | 碎叶    |  35000
  7 | 孙策 |  25 | 江东    |  32000
(4 行记录)
```

`BETWEEN`包含两个边界，等价于同一表达式上的`>=`和`<=`组合。处理时间范围时，应根据业务需要明确结束边界，避免把下一天的记录遗漏或重复计算。

> **子查询**

下面的查询使用未关联的子查询配合`EXISTS`。只要子查询找到至少一行，外层就会返回`company`的所有年龄；如果没有符合条件的薪资，外层不会返回任何行。`EXISTS`关注“是否存在行”，并不使用子查询的列值。

```postgresql
postgres=# SELECT age FROM company WHERE EXISTS (SELECT id FROM company WHERE salary >= 40000);
 age 
-----
  28
  30
  22
  26
  24
  20
  25
  35
  23
(9 行记录)
```

下面的查询把子查询作为标量表达式，与`>`进行比较。标量子查询必须最多返回一行；如果薪资等于 30000 的记录有多行，执行时会报错，应改用`IN`、`EXISTS`或聚合等写法。

```postgresql
postgres=# SELECT * FROM company WHERE age > (SELECT age FROM company WHERE salary = 30000 );
 id | name | age | address | salary 
----+------+-----+---------+--------
  8 | 张良 |  35 | 颍川    |  40000
(1 行记录)
```

## AND & OR

[逻辑运算符参考 ↪](https://www.postgresql.org/docs/18/functions-comparison.html)

`AND`、`OR`和`NOT`是逻辑运算符，用于组合多个布尔条件。`AND`要求所有条件为真，`OR`只要求至少一个条件为真；涉及`NULL`时遵循 SQL 的三值逻辑。

> **`AND`**

`AND`运算符表示所有连接的条件都必须成立。

在 WHERE 子句中，AND 的使用语法如下：

```postgresql
SELECT column1, column2, columnN
FROM table_name
WHERE [condition1] AND [condition2]...AND [conditionN];
```

以下实例读取 AGE 字段大于 25 且 SALARY 字段大于等于 30000 的所有记录：

```postgresql
postgres=# SELECT * FROM company WHERE age > 25 AND salary >= 30000;
 id | name | age | address | salary 
----+------+-----+---------+--------
  2 | 吕布 |  30 | 洛阳    |  30000
  4 | 李白 |  26 | 碎叶    |  35000
  8 | 张良 |  35 | 颍川    |  40000
(3 行记录)
```

> **`OR`**

`OR`运算符表示多个条件中只需满足其中任意一个即可。为避免复杂条件受优先级影响，建议使用括号明确分组；默认优先级为`NOT`高于`AND`，`AND`高于`OR`。

在 WHERE 子句中，OR 的使用语法如下：

```postgresql
SELECT column1, column2, columnN
FROM table_name
WHERE [condition1] OR [condition2]...OR [conditionN]
```

以下实例读取 AGE 字段大于等于 25 或 SALARY 字段大于等于 30000 的所有记录：

```postgresql
postgres=# SELECT * FROM company WHERE age > 25 OR salary >= 30000;
 id | name | age | address | salary 
----+------+-----+---------+--------
  1 | 赵云 |  28 | 常山    |  25000
  2 | 吕布 |  30 | 洛阳    |  30000
  4 | 李白 |  26 | 碎叶    |  35000
  7 | 孙策 |  25 | 江东    |  32000
  8 | 张良 |  35 | 颍川    |  40000
(5 行记录)
```

## LIKE

[模式匹配参考 ↪](https://www.postgresql.org/docs/18/functions-matching.html)

`LIKE`用于按模式匹配字符值。模式会匹配整个字符串，而不是只匹配其中一段；需要匹配任意位置时，应在模式两侧按需放置`%`。

在`LIKE`模式中，主要有以下两种通配符：

- 百分号`%`：匹配任意长度的字符序列，也可以匹配空序列。
- 下划线`_`：匹配恰好一个字符。

如果模式中没有`%`或`_`，`LIKE`与等号`=`通常得到相同的匹配结果。通配符需要按字面匹配时，要使用`ESCAPE`指定转义字符。

以下是使用 LIKE 子句搭配百分号 **%** 和下划线 **_** 从数据库中获取数据的通用语法：

```postgresql
SELECT FROM <table_name> WHERE column LIKE 'XXXX%';
或者
SELECT FROM <table_name> WHERE column LIKE '%XXXX%';
或者
SELECT FROM <table_name> WHERE column LIKE 'XXXX_';
或者
SELECT FROM <table_name> WHERE column LIKE '_XXXX';
或者
SELECT FROM <table_name> WHERE column LIKE '_XXXX_';
```

`LIKE`可以和`WHERE`中的其他条件通过`AND`、`OR`和`NOT`组合。示例中的`XXXX`只是占位符，实际应替换为要匹配的字符序列。

上面的语法示意省略了`SELECT`列表；实际执行时应在`SELECT`后写出列名或`*`。

**实例**

下面通过示例对比`%`和`_`的匹配差异：

| 实例                             | 描述                                                   |
| :------------------------------- | :----------------------------------------------------- |
| WHERE SALARY::text LIKE '200%'   | 找出 SALARY 字段中以 200 开头的数据。                  |
| WHERE SALARY::text LIKE '%200%'  | 找出 SALARY 字段中含有 200 字符的数据。                |
| WHERE SALARY::text LIKE '_00%'   | 找出 SALARY 字段中在第二和第三个位置上有 00 的数据。   |
| WHERE SALARY::text LIKE '2\_%_%' | 找出 SALARY 字段中以 2 开头的字符长度大于 3 的数据。   |
| WHERE SALARY::text LIKE '%2'     | 找出 SALARY 字段中以 2 结尾的数据                      |
| WHERE SALARY::text LIKE '_2%3'   | 找出 SALARY 字段中 2 在第二个位置上并且以 3 结尾的数据 |
| WHERE SALARY::text LIKE '2___3'  | 找出 SALARY 字段中以 2 开头，3 结尾并且是 5 位数的数据 |

`LIKE`主要用于字符类型比较；对数值列进行模式匹配时，需要像示例一样显式转换为文本。若只需要数值范围判断，直接使用数值比较通常更清晰也更容易利用索引。

`ILIKE`是 PostgreSQL 提供的不区分大小写的匹配运算符；是否区分大小写还会受到排序规则和数据类型的影响。

下面实例将找出 AGE 以 3 开头的数据：

```postgresql
postgres=# SELECT * FROM company WHERE age::TEXT LIKE '3%';
 id | name | age | address | salary 
----+------+-----+---------+--------
  2 | 吕布 |  30 | 洛阳    |  30000
  8 | 张良 |  35 | 颍川    |  40000
(2 行记录)
```

下面实例将找出 ADDRESS 字段中含有 **阳** 字符的数据：

```postgresql
postgres=# SELECT * FROM company WHERE address LIKE '%阳%';
 id | name | age | address | salary 
----+------+-----+---------+--------
  2 | 吕布 |  30 | 洛阳    |  30000
(1 行记录)
```

## LIMIT

[LIMIT/OFFSET 参考 ↪](https://www.postgresql.org/docs/18/queries-limit.html)

`LIMIT`限制`SELECT`返回的最大行数，`OFFSET`跳过结果集开头的指定行数。`OFFSET`从`0`开始计数，因此`OFFSET 2`表示跳过前两行。

语法结构：

```postgresql
SELECT column1, column2, columnN
FROM table_name
LIMIT [no of rows]
```

下面是 LIMIT 子句与 OFFSET 子句一起使用时的语法：

```postgresql
SELECT column1, column2, columnN 
FROM table_name
LIMIT [no of rows] OFFSET [row num]
```

**实例**

下面实例限制返回数量为 4 行：

```postgresql
postgres=# SELECT * FROM company LIMIT 4;
 id | name | age | address | salary 
----+------+-----+---------+--------
  1 | 赵云 |  28 | 常山    |  25000
  2 | 吕布 |  30 | 洛阳    |  30000
  3 | 貂蝉 |  22 | 长安    |  18000
  4 | 李白 |  26 | 碎叶    |  35000
(4 行记录)
```

如果需要分页，可以配合`OFFSET`跳过前面的行。分页结果必须配合稳定且足够唯一的`ORDER BY`，否则数据库没有义务保持行的顺序，翻页结果可能重复或遗漏；大偏移量分页还可能带来较高扫描成本。

下面是一个实例，从第三位开始提取 4 个记录：

```postgresql
postgres=# SELECT * FROM company LIMIT 4 OFFSET 2;
 id | name | age | address | salary 
----+------+-----+---------+--------
  3 | 貂蝉 |  22 | 长安    |  18000
  4 | 李白 |  26 | 碎叶    |  35000
  5 | 韩信 |  24 | 淮阴    |  28000
  6 | 妲己 |  20 | 青丘    |  15000
(4 行记录)
```

## ORDER BY

[ORDER BY 参考 ↪](https://www.postgresql.org/docs/18/queries-order.html)

`ORDER BY`用于按一个或多个表达式对结果排序。默认顺序是升序`ASC`；可以用`DESC`降序排列，也可以用`NULLS FIRST`或`NULLS LAST`明确空值位置。默认情况下，升序将`NULL`排在末尾，降序将`NULL`排在开头。

语法格式：

```postgresql
SELECT column-list
FROM table_name
[WHERE condition]
[ORDER BY column1, column2, .. columnN] [ASC | DESC];
```

## GROUP BY

[GROUP BY 与 HAVING 参考 ↪](https://www.postgresql.org/docs/18/queries-table-expressions.html)

`GROUP BY`把输入行按照一个或多个分组表达式归并为组，通常与`COUNT`、`SUM`、`AVG`等聚合函数一起生成统计结果。分组键相同的行属于同一组，`NULL`值在同一分组键中会归为一组。

在`SELECT`语句的书写顺序中，`GROUP BY`位于`WHERE`之后、`HAVING`之前，`ORDER BY`位于分组和过滤之后。

语法格式：

```postgresql
SELECT column-list
FROM table_name
WHERE [ conditions ]
GROUP BY column1, column2....columnN
ORDER BY column1, column2....columnN
```

`GROUP BY`必须放在`WHERE`之后、`ORDER BY`之前；这是语句的语法顺序，不等同于所有表达式的实际执行顺序。

如果查询包含分组，`SELECT`列表中未参与聚合的列通常必须出现在`GROUP BY`中；当 PostgreSQL 能根据主键等唯一约束确定函数依赖时，也可能允许省略相关列。分组表达式不局限于简单列名。

## HAVING

[HAVING 参考 ↪](https://www.postgresql.org/docs/18/queries-table-expressions.html)

`HAVING`用于筛选分组后的组，可以在条件中使用聚合函数或分组表达式。

`WHERE`在分组前过滤单行，`HAVING`在分组和聚合后过滤组；能在`WHERE`完成的条件应尽量提前过滤，以减少需要分组的数据量。

下面是 HAVING 子句在 SELECT 查询中的位置：

```postgresql
SELECT
FROM
WHERE
GROUP BY
HAVING
ORDER BY
```

`HAVING`必须位于`GROUP BY`之后、`ORDER BY`之前。即使没有显式`GROUP BY`，聚合查询也可以使用`HAVING`，此时输入行被视为一个组。

```postgresql
SELECT column1, column2
FROM table1, table2
WHERE [ conditions ]
GROUP BY column1, column2
HAVING [ conditions ]
ORDER BY column1, column2
```

**实例**

筛选高绩效部门（A级员工≥2人的部门）

```postgresql
SELECT department, COUNT(*) AS a_grade_count 
FROM emp_performance 
WHERE grade = 'A' 
GROUP BY department 
HAVING COUNT(*) >= 2;
```

结果示例：

```postgresql
 department | a_grade_count 
------------+---------------
 技术部     |             2
(1 行记录)
```

## WITH

[WITH 查询（CTE）参考 ↪](https://www.postgresql.org/docs/18/queries-with.html)

PostgreSQL 中的`WITH`语句也叫 CTE（公共表表达式）。它为当前语句命名一个查询结果，主查询或后续 CTE 可以像引用表一样引用它；CTE 只在当前语句中有效，也不等同于一定会物化的临时表。

语法格式：

1）**基础语法**

```postgresql
WITH cte_name [(column1, column2, ...)] AS (
    -- 子查询（SELECT/INSERT/UPDATE/DELETE）
    SELECT ...
)
-- 主查询
SELECT * FROM cte_name;
```

- `cte_name`：当前语句内引用的 CTE 名称。
- `(column1, column2, ...)`：可选的输出列名列表；省略时由子查询的输出列名决定。
- **子查询**：可以是`SELECT`，也可以是带`RETURNING`的`INSERT`、`UPDATE`或`DELETE`。

示例：

```postgresql
WITH sales_summary AS (
    SELECT region, SUM(amount) AS total 
    FROM orders 
    GROUP BY region
)
SELECT * FROM sales_summary WHERE total > 10000;
```

2）**多重CTE**

可以定义多个 CTE，用逗号分隔；后面的 CTE 可以引用前面已经定义的 CTE：

```postgresql
WITH 
    cte1 AS (SELECT ...),
    cte2 AS (SELECT ...)
SELECT * FROM cte1 JOIN cte2 ON ...;
```

示例：

```postgresql
WITH 
    regional_sales AS (
        SELECT region, SUM(amount) AS total 
        FROM orders 
        GROUP BY region
    ),
    top_regions AS (
        SELECT region 
        FROM regional_sales 
        WHERE total > (SELECT AVG(total) FROM regional_sales)
    )
SELECT * FROM orders WHERE region IN (SELECT region FROM top_regions);
```

3）**递归语法（`RECURSIVE`）**

`WITH RECURSIVE`用于递归查询，适合遍历层次结构或图结构数据：

```postgresql
WITH RECURSIVE cte_name AS (
    -- 非递归项（基础查询）
    SELECT ... FROM table WHERE ...
    UNION [ALL]
    -- 递归项（引用自身）
    SELECT ... FROM cte_name JOIN table ON ...
)
SELECT * FROM cte_name;
```

**说明**：

- **`UNION ALL`**：保留重复行；`UNION`会在每轮结果中去重。
- **终止条件**：递归项必须能够结束（如`WHERE n < 100`），否则可能无限生成结果；遍历图结构时还要处理循环路径。

**示例**（计算 1 到 100 的和）：

```postgresql
WITH RECURSIVE t(n) AS (
    VALUES (1)          -- 初始值
    UNION ALL
    SELECT n+1 FROM t WHERE n < 100  -- 递归终止条件
)
SELECT SUM(n) FROM t;
```

4）**数据修改语句**

`WITH`可以与`INSERT`、`UPDATE`或`DELETE`结合。数据修改 CTE 通常通过`RETURNING`把变更行提供给顶层语句：

```postgresql
WITH moved_rows AS (
    DELETE FROM products 
    WHERE date < '2025-01-01'
    RETURNING *
)
INSERT INTO archive_products 
SELECT * FROM moved_rows;
```

> **注意**：数据修改语句必须位于顶层语句的`WITH`中；同一条语句中的数据修改 CTE 在同一快照下执行，彼此执行顺序不可依赖，跨 CTE 传递结果应使用`RETURNING`。

总结：

1. **作用域**：CTE 仅在当前语句中有效。
2. **物化策略**：CTE 默认由规划器决定是否物化；PostgreSQL 12+支持`MATERIALIZED`和`NOT MATERIALIZED`，应根据复用次数和过滤条件选择，并用`EXPLAIN`验证。
3. **递归限制**：确保递归能够终止；处理图结构时可用`UNION`去重或记录已访问路径来避免循环。

## DISTINCT

[DISTINCT 参考 ↪](https://www.postgresql.org/docs/18/queries-select-lists.html)

在 PostgreSQL 中，`DISTINCT`紧跟在`SELECT`之后，用于删除结果集中重复的行。判断是否重复时，会比较`SELECT`列表中的全部输出表达式；`NULL`在去重比较中视为相等。

因此，`SELECT DISTINCT name`只保证名称不重复，并不会保留表中某一行的其他列。若要按某个键保留“最优”或“最新”一行，可使用 PostgreSQL 特有的`DISTINCT ON`并配合`ORDER BY`明确优先级；没有足够的排序条件时，保留哪一行是不确定的。

语法格式：

```postgresql
SELECT DISTINCT column1, column2,.....columnN
FROM table_name
WHERE [condition]
```

**实例**

插入数据：

```postgresql
INSERT INTO company (id, name, age, address, salary)
VALUES 
    (10, '貂蝉', 22, '长安', 20000.00),
    (11, '赵云', 28, '常山', 5000.00),
    (12, '韩信', 24, '淮阴', 5000.00),
```

接下来我们找出 COMPANY 表中的所有 NAME：

```postgresql
postgres=# SELECT name FROM COMPANY;

------
 赵云
 吕布
 貂蝉
 李白
 韩信
 妲己
 孙策
 张良
 大乔
 貂蝉
 赵云
 韩信
(12 行记录)
```

现在我们在 SELECT 语句中使用 DISTINCT 子句：

```postgresql

 name 
------
 貂蝉
 韩信

 妲己

(9 行记录)
```

从结果可以看到，结果集中的重复名称已经被过滤；`DISTINCT`不会修改源表中的数据。

## 汇总指令

下面汇总本章常用的查询、过滤、排序和分页写法，适合作为速查表。占位符需要替换为实际表名、列名和条件。

```postgresql
-- 查询指定表中的所有列数据
SELECT * FROM <table_name>
-- 条件查询：指定条件
SELECT * FROM <table_name> WHERE <condition>
-- 条件查询：组合查询，结合逻辑运算符
SELECT * FROM <table_name> WHERE <condition> [AND, OR, NOT] <condition>
-- 条件查询：指定列包含 xxx
SELECT * FROM <table_name> WHERE <column> LIKE '%xxx%';
-- 条件查询：指定列以 xxx 开头> LIKE 'xxx%';
-- 条件查询：指定列以 xxx 结尾
SELECT * FROM <table_name> WHERE <column> LIKE '%xxx';
-- 条件查询：指定列的值为/不为 a 或者 b 的
SELECT * FROM <table_name> WHERE <column> IN (a, b);
SELECT * FROM <table_name> WHERE <column> NOT IN (a, b);
-- 条件查询：指定列的值在 [a, b] 区间范围以内的
SELECT * FROM students WHERE <column>  BETWEEN a AND b;
-- 查询数据并排序
SELECT * FROM <table_name> ORDER BY <sort_column_name> [DESC, ASC]
-- 删除重复行
SELECT DISTINCT column FROM <table_name>
-- 条件表达式
SELECT column1, (column2 + column3) / 2 AS <column_name>, column4 FROM <table_name>
-- 查询指定表中的指定列数据
SELECT column1, column2, ... FROM table_name [WHERE condition];
-- 分页查询
SELECT * FROM <table_name> LIMIT [no of rows] OFFSET [row num]
```

# 清空数据 TRUNCATE

[TRUNCATE 参考 ↪](https://www.postgresql.org/docs/18/sql-truncate.html)

`TRUNCATE`一次清空一个或多个表的全部行，不支持`WHERE`逐行筛选。它通常比无条件`DELETE`更快，但会取得表级`ACCESS EXCLUSIVE`锁；执行前要确认不会阻塞并发读写。

`RESTART IDENTITY`会重置被清空表所拥有的序列，默认行为是`CONTINUE IDENTITY`；`CASCADE`会继续清空引用关系中的表，影响范围必须明确。`TRUNCATE`可以在事务中回滚，但仍应谨慎处理生产数据。

语法格式：

```postgresql
TRUNCATE TABLE <table_name> [CASCADE | RESTART IDENTITY];
```

代码示例：

```postgresql
-- 清空单个表
TRUNCATE TABLE users;
-- 清空多个表（逗号分隔）
TRUNCATE TABLE users, orders, products;
-- 级联清空外键关联的表（避免外键约束错误）
TRUNCATE TABLE orders CASCADE;
-- 重置自增序列（如SERIAL主键从1开始）
TRUNCATE TABLE users RESTART IDENTITY;
```
