# 数据库操作

[数据库管理参考 ↪](https://www.postgresql.org/docs/18/managing-databases.html)

PostgreSQL 的`数据库（database）`是组织 SQL 对象的顶层容器。一个正在运行的 PostgreSQL 实例（数据库集群）可以包含多个数据库；每个数据库内部再包含模式、表、视图、函数等对象。

```text
PostgreSQL 实例（数据库集群）
├── 数据库 learn_db
│   ├── 模式 app
│   └── 表 app.users
├── 数据库 report_db
└── 数据库 postgres
```

需要注意：

- 数据库角色在整个实例中有效，但表、模式和函数只属于某一个数据库。
- 普通 SQL 不能直接跨数据库查询；需要分别连接数据库，或使用 FDW、逻辑复制等专门方案。
- `postgres`、`template0` 和 `template1` 是初始化集群时通常创建的数据库。`postgres` 主要作为默认连接入口，两个模板数据库用于创建新数据库。
- 数据库名称最长为 63 字节，建议使用小写字母、数字和下划线。

# 创建数据库

## 使用 SQL 创建

创建数据库需要超级用户或具有 `CREATEDB` 属性的角色。最简单的语句如下：

```postgresql
CREATE DATABASE learn_db;
```

也可以显式指定数据库所有者：

```postgresql
CREATE DATABASE learn_db OWNER app_owner;
```

如果指定的所有者不是当前角色，执行者还必须能够通过 `SET ROLE` 切换为该角色；超级用户不受此限制。

数据库所有者可以管理数据库，并通常可以管理其中由它创建的对象。为应用创建数据库时，建议使用专门的所有者角色，而不是应用登录角色：

```postgresql
-- app_owner 是 NOLOGIN 角色，app_user 是应用登录角色
CREATE DATABASE app_db OWNER app_owner;
```

常用的 `CREATE DATABASE` 选项如下：

```text
CREATE DATABASE name
    [ OWNER user_name ]
    [ TEMPLATE template_name ]
    [ ENCODING encoding ]
    [ LOCALE locale ]
    [ TABLESPACE tablespace_name ]
    [ ALLOW_CONNECTIONS allow_connections ]
    [ CONNECTION LIMIT connection_limit ]
    [ IS_TEMPLATE is_template ];
```

其中：

- `OWNER` 指定数据库所有者；省略时默认使用执行命令的角色。
- `TEMPLATE` 指定从哪个数据库复制，默认是 `template1`。
- `ENCODING` 和 `LOCALE` 控制字符编码、排序规则和字符分类规则。
- `TABLESPACE` 指定数据库文件使用的表空间，日常学习通常使用默认表空间。
- `ALLOW_CONNECTIONS false` 禁止新连接，但不会自动断开已有连接。
- `CONNECTION LIMIT` 限制并发连接数，`-1` 表示不限制。
- `IS_TEMPLATE true` 表示该数据库可以被具有 `CREATEDB` 权限的角色作为模板复制。

`CREATE DATABASE` 不能放在事务块中执行。下面这种写法会失败：

```postgresql
BEGIN;
CREATE DATABASE test_db;
COMMIT;
```

PostgreSQL 不支持 `CREATE DATABASE IF NOT EXISTS`。需要重复执行脚本时，应先查询数据库是否存在，再决定是否创建：

```postgresql
SELECT 1
FROM pg_database
WHERE datname = 'learn_db';

-- 确认查询没有返回结果后，再单独执行
CREATE DATABASE learn_db;
```

也可以在 Shell 中用 `createdb` 的退出状态实现检查后创建：

```shell
psql -d postgres -tAc "SELECT 1 FROM pg_database WHERE datname = 'learn_db'" | grep -q 1 || createdb learn_db
```

## 使用命令行创建

`createdb` 是 `CREATE DATABASE` 的命令行封装：

```shell
createdb learn_db
```

指定所有者和模板：

```shell
createdb -O app_owner -T template0 app_db
```

需要明确连接到某个实例时，使用连接参数：

```shell
createdb -h localhost -p 5432 -U db_admin -O app_owner app_db
```

执行命令的数据库角色必须具有 `CREATEDB` 权限或是超级用户；操作系统用户和数据库角色是两个不同概念。

## 使用图形化工具

pgAdmin 和 DBeaver 都可以通过“创建数据库”功能完成相同操作。图形化工具只是发送 `CREATE DATABASE` 请求，最终仍受数据库角色权限、服务器地址和端口限制。

[CREATE DATABASE 参考 ↪](https://www.postgresql.org/docs/18/sql-createdatabase.html)

# 查看数据库

## 使用 psql 元命令

进入任意数据库后，可以使用以下命令查看数据库列表：

```postgresql
\l
\l+
```

`\l+` 会显示更详细的信息，例如数据库大小、表空间和连接限制。也可以在 Shell 中执行：

```shell
psql -l
psql -l -U db_admin -h localhost -p 5432
```

查看当前连接：

```postgresql
\conninfo
SELECT current_database(), current_user;
```

`psql` 元命令不需要分号；SQL 语句通常需要以分号结束。

## 查询系统目录

`pg_database` 保存数据库级元数据。`pg_roles` 中的角色是实例级对象，可以用 `pg_get_userbyid` 将所有者 OID 转换为角色名：

```postgresql
SELECT
    datname AS database_name,
    pg_get_userbyid(datdba) AS owner,
    pg_encoding_to_char(encoding) AS encoding,
    datcollate,
    datctype,
    datallowconn AS allow_connections,
    datconnlimit AS connection_limit,
    datistemplate AS is_template
FROM pg_database
ORDER BY datname;
```

查看某一个数据库的连接限制和允许连接状态：

```postgresql
SELECT
    datname,
    datallowconn,
    datconnlimit
FROM pg_database
WHERE datname = 'learn_db';
```

数据库大小可以使用内置函数查看：

```postgresql
SELECT
    datname,
    pg_size_pretty(pg_database_size(datname)) AS size
FROM pg_database
ORDER BY pg_database_size(datname) DESC;
```

# 连接和切换数据库

## 使用 psql 连接

连接数据库时，常用参数如下：

```shell
psql -d learn_db
psql -U app_user -d learn_db
psql -h localhost -p 5432 -U app_user -d learn_db
```

- `-d`（`--dbname`）：数据库名称。
- `-U`（`--username`）：数据库角色名称。
- `-h`（`--host`）：服务器主机名、IP 地址，或 Unix socket 目录。
- `-p`（`--port`）：服务器端口，默认通常是 `5432`。

如果省略 `-U`，`psql` 通常使用当前操作系统用户名；如果省略 `-d`，它通常尝试连接到与用户名同名的数据库。为了避免连接到错误的实例，脚本和生产操作建议显式指定 `-h`、`-p`、`-U` 和 `-d`。

需要密码认证时可以让 `psql` 提示输入密码：

```shell
psql -h localhost -p 5432 -U app_user -d learn_db -W
```

不要把真实密码直接写在命令行参数中；命令行可能被 Shell 历史或进程列表记录。自动化场景可以使用权限正确的 `.pgpass` 文件或其他密钥管理方案。

## 在 psql 中切换

连接后使用 `\c`（或 `\connect`）切换数据库：

```postgresql
\c learn_db
\c learn_db app_user
\c postgres
```

切换时会建立新的连接，之前未提交的事务不能依赖切换来保存。切换成功后使用以下命令确认连接对象：

```postgresql
\conninfo
SELECT
    current_database(),
    session_user,
    current_user;
```

`session_user` 是最初登录的角色，`current_user` 可能因 `SET ROLE` 而变化。连接数据库需要同时满足认证规则和数据库的 `CONNECT` 权限；具体角色权限见[第 03 章：用户管理](./第03章%20用户管理.md)。

[psql 连接参考 ↪](https://www.postgresql.org/docs/18/app-psql.html)

# 修改数据库属性

使用 `ALTER DATABASE` 修改数据库名称、所有者、连接限制或会话默认配置：

```postgresql
-- 修改所有者
ALTER DATABASE learn_db OWNER TO app_owner;

-- 修改并发连接数
ALTER DATABASE learn_db CONNECTION LIMIT 20;

-- 禁止新连接（已有连接不会被自动断开）
ALTER DATABASE learn_db ALLOW_CONNECTIONS false;

-- 设置该数据库中新会话的时区
ALTER DATABASE learn_db SET timezone TO 'UTC';

-- 恢复为系统或集群默认值
ALTER DATABASE learn_db RESET timezone;
```

修改数据库所有者时，执行者需要具有 `CREATEDB` 权限，并且能够通过 `SET ROLE` 切换为新的所有者；超级用户自动具备这些条件。

重命名数据库：

```postgresql
ALTER DATABASE learn_db RENAME TO learn_db_archive;
```

重命名时当前会话不能连接到正在重命名的数据库。应先连接到 `postgres` 或其他管理数据库，再执行重命名；重命名后，应用的后续连接配置也要改用新名称。

`ALTER DATABASE ... SET` 设置的是数据库级会话默认值，只对之后建立的新会话生效；已经连接的会话需要重新连接。数据库级配置不会自动复制到从该数据库创建的新数据库中。

## 数据库级权限

数据库权限与数据库属性是两回事。可以使用 `GRANT` 和 `REVOKE` 管理谁能连接或在数据库中创建对象：

```postgresql
GRANT CONNECT ON DATABASE learn_db TO app_user;
GRANT TEMPORARY ON DATABASE learn_db TO app_user;

-- 谨慎撤销所有角色的默认连接权限
REVOKE CONNECT ON DATABASE learn_db FROM PUBLIC;
```

撤销 `PUBLIC` 的 `CONNECT` 后，必须为需要访问的角色单独授予 `CONNECT`，否则包括管理员在内的普通角色都可能无法连接。模式和表权限还需要另外设置，不能由数据库级 `CONNECT` 自动授予。

# 模板数据库

## template1 和 template0

`CREATE DATABASE` 默认复制 `template1`。如果在 `template1` 中创建了自定义对象，之后新建的数据库也会复制这些对象。

`template0` 是初始化集群时的干净模板，只包含 PostgreSQL 的标准对象。需要创建一个不包含站点自定义对象的数据库，或需要指定与 `template1` 不同的编码、区域设置时，可以复制 `template0`：

```postgresql
CREATE DATABASE clean_db
    TEMPLATE template0;
```

命令行写法：

```shell
createdb -T template0 clean_db
```

注意：

- 不要在 `template0` 中创建业务表或修改配置；它应保持为干净模板。
- 复制模板时，源数据库不能有其他会话连接。
- `template1` 中的数据库级授权和 `ALTER DATABASE` 配置不会复制到新数据库。
- 区域设置名称由操作系统提供，同一个 `LOCALE` 在 macOS、Linux 和 Windows 上可能不同。

## 把普通数据库作为模板

任意数据库都可以被指定为模板，但复制过程中不能有其他连接。只有数据库所有者或超级用户可以使用未标记为模板的数据库进行复制；将 `datistemplate` 设置为 `true` 后，具有 `CREATEDB` 权限的角色也可以使用它。

通常不需要把业务数据库标记为模板。若确实要创建模板，可以由管理员执行：

```postgresql
ALTER DATABASE seed_db IS_TEMPLATE true;
```

# 删除数据库

## 基本删除

删除数据库会删除其中的所有模式、表、数据、函数和其他对象，操作不可撤销。只有数据库所有者或超级用户可以删除数据库：

```postgresql
DROP DATABASE IF EXISTS learn_db;
```

`DROP DATABASE` 不能在事务块中执行，也不能从正在被删除的数据库连接中执行。删除前先连接到另一个数据库：

```postgresql
\c postgres
DROP DATABASE learn_db;
```

## 存在活动连接时删除

先查看目标数据库的连接：

```postgresql
SELECT
    pid,
    usename,
    application_name,
    client_addr,
    state
FROM pg_stat_activity
WHERE datname = 'learn_db'
ORDER BY pid;
```

普通角色通常只能看到自己的会话；查看或终止其他角色的会话需要相应的监控或管理权限。

确认要终止这些连接后，PostgreSQL 18 可以使用 `WITH (FORCE)`：

```postgresql
DROP DATABASE learn_db WITH (FORCE);
```

它会尝试终止目标数据库的现有连接，然后删除数据库。生产环境执行前应确认连接来源、备份和业务影响；不确定时先停止应用或使用维护窗口。

命令行等价写法：

```shell
dropdb --force learn_db
```

`WITH (FORCE)` 和 `--force` 都可能中断正在运行的事务，不应作为日常“解决连接问题”的快捷方式。

[DROP DATABASE 参考 ↪](https://www.postgresql.org/docs/18/sql-dropdatabase.html)

# 备份与恢复

删除或迁移数据库前，建议先备份。`pg_dump` 备份单个数据库中的对象和数据：

```shell
pg_dump -Fc -d learn_db -f learn_db.dump
```

创建恢复目标并还原：

```shell
createdb learn_db_restore
pg_restore -d learn_db_restore learn_db.dump
```

也可以生成纯 SQL 文件：

```shell
pg_dump -d learn_db > learn_db.sql
createdb learn_db_restore
psql -d learn_db_restore -f learn_db.sql
```

`pg_dump` 只备份一个数据库，不包含实例级角色和表空间等全局对象。需要同时备份这些全局对象时，可以执行：

```shell
pg_dumpall --globals-only > globals.sql
```

恢复全局对象通常需要管理员权限：

```shell
psql -d postgres -f globals.sql
```

恢复前请检查目标数据库的所有者、扩展、编码和权限；不要在没有验证备份可恢复性的情况下删除源数据库。

[备份工具参考 ↪](https://www.postgresql.org/docs/18/backup-dump.html)

# 常见问题

## `permission denied to create database`

当前数据库角色没有 `CREATEDB` 属性，也不是超级用户。请让管理员授予权限，或使用专门的数据库管理员角色：

```postgresql
ALTER ROLE db_admin CREATEDB;
```

只为临时管理工作授予 `CREATEDB`，完成后可以撤销：

```postgresql
ALTER ROLE db_admin NOCREATEDB;
```

## `database "xxx" already exists`

数据库名称已经存在。先使用 `\l` 或 `pg_database` 确认，重复执行脚本可以先查询再创建，也可以选择新的数据库名称。

## `CREATE DATABASE cannot run inside a transaction block`

`CREATE DATABASE`、`DROP DATABASE` 等数据库级操作不能放在 `BEGIN` 和 `COMMIT` 之间。关闭客户端的手动事务模式，或在独立的 `psql -c` 命令中执行。

## `cannot drop the currently open database`

先切换到其他数据库，再删除目标数据库：

```postgresql
\c postgres
DROP DATABASE learn_db;
```

## `database is being accessed by other users`

说明仍有其他会话连接目标数据库。先查询 `pg_stat_activity`，确认来源后停止应用、等待会话结束，或在确认影响后使用 `DROP DATABASE ... WITH (FORCE)`。

## 连接到了错误的数据库或实例

使用以下命令检查当前连接：

```postgresql
\conninfo
SELECT version(), current_database(), current_user;
```

连接时显式指定 `-h`、`-p`、`-U` 和 `-d`，不要只依赖默认值。不同 PostgreSQL 实例可能使用不同的数据目录、端口和角色。

## `permission denied for database learn_db`

角色通过了密码或其他认证，但没有数据库的 `CONNECT` 权限：

```postgresql
GRANT CONNECT ON DATABASE learn_db TO app_user;
```

这只解决数据库级连接权限；连接后访问模式、表、序列仍需额外授权。

# 操作检查清单

- 创建数据库前确认所有者、编码、区域设置和连接限制。
- 应用数据库使用专门的 `NOLOGIN` 所有者角色，应用账号只获得所需对象权限。
- 生产环境不要随意修改 `template0`，也不要把业务数据库无计划地标记为模板。
- 删除数据库前检查活动连接并完成可验证的备份。
- 使用 `\conninfo` 和 `SELECT version()` 确认目标实例，避免误操作其他环境。
- 不把密码写进命令行、SQL 文件或版本库；认证和角色权限分别检查。
- 数据库级 `CONNECT`、模式级 `USAGE` 和表级读写权限需要分别配置。

# 小结

本章介绍了数据库的层次、创建方式、所有者与属性、查看和切换连接、模板数据库、数据库级权限、删除以及备份恢复。后续学习表结构时，应先连接到正确的目标数据库，再在其中创建模式和表。
