# 概述

[PostgreSQL ↪](https://postgresql.ac.cn/) 是一款功能强大的 **开源对象-关系型数据库管理系统（ORDBMS）**。它起源于 1986 年加州大学伯克利分校的 POSTGRES 项目，经过长期发展，已经成为企业应用、数据分析和地理信息系统中常用的关系型数据库。

PostgreSQL 采用客户端/服务器（Client/Server）架构：

- 服务器（Server）负责保存数据、执行 SQL、管理事务和处理并发连接。
- 客户端（Client）负责向服务器发送请求并显示结果，`psql`、pgAdmin 和 DBeaver 都属于客户端工具。
- 客户端与服务器可以在同一台电脑上，也可以通过网络连接到远程服务器。

## 版本说明

PostgreSQL 的版本号从 10 开始采用两段式格式：`主版本号.次版本号`。例如：

- `18`：主版本，通常包含新功能，主版本之间升级可能需要迁移数据。
- `18.6`：PostgreSQL 18 的次版本，主要包含错误修复和安全修复，通常可以直接升级。

截至 2026 年 8 月，PostgreSQL 18 是最新的主版本，当前次版本为 18.6。安装命令使用 `postgresql@18` 指定主版本，不把 `18.6` 写死在命令中，这样后续执行 `brew upgrade` 时仍能获得 18.x 的最新修复。

> 提示：版本信息以 [官方版本策略 ↪](https://www.postgresql.org/support/versioning/) 和 [PostgreSQL 18 发布说明 ↪](https://www.postgresql.org/docs/18/release-18.html) 为准。

## 核心特性

- 标准 SQL 与事务：支持常用 SQL 标准、ACID（原子性、一致性、隔离性、持久性）事务、视图、触发器、窗口函数和 CTE（公共表表达式）。
- 多版本并发控制（MVCC）：读操作通常不阻塞写操作，写操作也不会让其他会话读到未提交数据，适合并发访问。
- 丰富的数据类型：除整数、文本、日期时间外，还支持 `JSONB`、数组、UUID、范围、网络地址和全文检索相关类型。
- 可扩展：可以安装扩展、定义自定义类型、函数、运算符和索引方法。常见扩展包括 GIS 场景的 PostGIS 和向量检索场景的 pgvector。
- 查询能力完整：支持 B-tree、GIN、GiST 等索引，以及并行查询、分区表、物化视图和逻辑复制等功能。
- 安全机制完善：提供角色与权限、SCRAM 密码认证、SSL/TLS 加密、行级安全策略（RLS）等机制。
- 跨平台：支持 Linux、Windows、macOS 等主流操作系统，也可以使用 Docker 或云服务部署。

> 提示：PostgreSQL 本体主要采用行存储，不应把“列存储”当作它的默认特性。分析场景通常结合合适的索引、分区、并行查询或专用扩展来优化。

## 常见应用场景

- Web 服务：作为 Django、FastAPI、Spring 等应用的业务数据库。
- 数据分析：执行复杂查询、聚合和报表，并与数据仓库或 ETL 工具配合使用。
- 地理信息系统（GIS）：通过 PostGIS 存储和查询地理空间数据。
- 半结构化数据：使用 `JSONB` 保存结构变化较快的数据，同时保留关系型查询和索引能力。
- 金融与物联网：利用事务、约束和并发控制保证数据的一致性。

PostgreSQL 使用宽松的 PostgreSQL License，允许个人和企业免费使用、修改和发布。

# ORDBMS 术语

在开始编写 SQL 前，先理解几个基本对象。可以把 PostgreSQL 的对象层次简单看成：

```text
PostgreSQL 实例（一个数据目录）
└── 数据库 database
    └── 模式 schema
        └── 表 table
            ├── 列 column
            └── 行 row
```

- 实例（instance）：一个正在运行的 PostgreSQL 服务器及其数据目录。一个实例可以包含多个数据库。
- 数据库（database）：一组相互关联的对象集合。连接 PostgreSQL 时，必须连接到某一个数据库。
- 模式（schema）：数据库中的命名空间，可以理解为给表、视图、函数等对象分组的目录。默认模式通常是 `public`。
- 数据表（table）：按行和列组织数据的对象，类似于电子表格，但可以增加约束、索引和权限。
- 列（column）：描述数据的一个属性，例如用户表中的 `name` 或 `email`；每一列都有自己的数据类型。
- 行（row）：一条完整记录，也叫元组（tuple），例如一个用户或一笔订单。
- 主键（primary key）：唯一标识一行数据的一个或多个列。每张表最多有一个主键，主键值不能重复且不能为 `NULL`。
- 外键（foreign key）：引用另一张表的主键或唯一键，用于建立表之间的关系并保证引用完整性。
- 复合键（composite key）：由多个列共同组成的主键或唯一约束，例如用 `order_id` 和 `product_id` 共同标识订单明细。
- 唯一约束（unique constraint）：要求列值不重复。它和主键都可以建立唯一索引，但一张表可以有多个唯一约束。
- 索引（index）：帮助数据库快速定位数据的辅助结构，类似于书籍目录。索引会占用空间，也会增加写入和维护成本，并非越多越好。
- 冗余（redundancy）：同一事实被重复保存。适度冗余有时可以换取查询性能，但无计划的冗余容易造成数据不一致；表设计通常先考虑规范化，再根据场景引入冗余。
- 事务（transaction）：一组要么全部成功、要么全部失败的操作，是保证数据一致性的基本单位。
- 扩展（extension）：为数据库增加额外类型、函数或操作符的可安装组件，例如 PostGIS 和 pgvector。

# 环境配置

> 本节以 macOS、Homebrew 和默认的 zsh 终端为例。Windows、Linux 或 Docker 的安装方式请参考 [官方安装页面 ↪](https://www.postgresql.org/download/)。

## 使用 Homebrew 安装 PostgreSQL 18

### 1. 检查 Homebrew

如果终端还不能识别 `brew`，请先按照 [Homebrew 官方文档 ↪](https://brew.sh/) 安装；已经安装的用户可以直接检查版本：

```shell
brew --version
```

### 2. 安装 PostgreSQL

```shell
brew update
brew install postgresql@18
```

`postgresql@18` 是 PostgreSQL 18 的 Homebrew 公式。它是 `keg-only` 公式，因此后面需要把它的 `bin` 目录加入 `PATH`。Homebrew 通常会在安装时创建默认数据目录：`$(brew --prefix)/var/postgresql@18`。

### 3. 配置命令行路径

macOS 默认使用 zsh。下面的命令只需执行一次：

```shell
echo 'export PATH="$(brew --prefix postgresql@18)/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

确认当前使用的是 PostgreSQL 18 的客户端：

```shell
command -v psql
psql --version
```

版本输出应类似 `psql (PostgreSQL) 18.x`。其中 `x` 会随着 Homebrew 的次版本更新而变化，不必与本文示例完全相同。

### 4. 启动 PostgreSQL 服务

推荐使用 Homebrew 管理后台服务：

```shell
brew services start postgresql@18
brew services list
```

`brew services start` 会在后台启动服务，并默认设置为登录后自动启动。如果只想临时启动、不设置自动启动，可以使用：

```shell
pg_ctl -D "$(brew --prefix)/var/postgresql@18" start
```

如果安装后提示数据目录不存在，才需要手动初始化一次：

```shell
initdb --locale=en_US.UTF-8 -E UTF-8 "$(brew --prefix)/var/postgresql@18"
```

> 不要对已经包含数据的目录重复执行 `initdb`，否则会报错；生产环境初始化或迁移前应先准备备份。

### 5. 验证服务

```shell
pg_isready
psql --version
psql -d postgres -c 'SELECT version();'
```

`pg_isready` 返回 `accepting connections` 表示服务器已经可以接受连接。`psql --version` 查看的是客户端版本，`SELECT version()` 查看的是实际连接到的服务器版本；两者在多版本环境下可能不同。

### 6. 首次连接

Homebrew 初始化的本地实例通常会创建一个与当前 macOS 用户同名的数据库角色。直接连接默认的 `postgres` 数据库即可：

```shell
psql -d postgres
```

如果希望创建一个专门用于学习的数据库，可以执行：

```shell
createdb learn_db
psql -d learn_db
```

`createdb learn_db` 创建的数据库默认归当前角色所有。需要额外的数据库角色时，再按提示执行下面的命令；

角色和权限管理见[第 03 章：用户管理](./第03章%20用户管理.md)。

```shell
createuser --interactive --pwprompt
```

学习环境可以选择是否允许超级用户，但业务应用通常不应使用超级用户。

连接远程服务器或需要明确指定连接参数时，使用以下格式：

```shell
psql -h localhost -p 5432 -U 用户名 -d 数据库名
```

请将“用户名”和“数据库名”替换为实际值。

`root` 不是 PostgreSQL 的默认学习用户，也不建议把操作系统的 `root` 账号当作数据库应用账号。

后续角色、密码和权限管理见[第 03 章：用户管理](./第03章%20用户管理.md)。

> **提示**：在 `psql` 中退出使用 `\q`，也可以按 <kbd>Ctrl</kbd> + <kbd>D</kbd>。

# 基本操作

进入 `psql` 后，可以使用反斜杠开头的元命令管理会话，也可以直接执行 SQL。示例中的 `postgres=#` 是 `psql` 提示符，不需要输入：

```postgresql
postgres=# \conninfo
postgres=# \l
postgres=# \c postgres
postgres=# \dt
postgres=# \du
postgres=# \h SELECT
postgres=# \?
postgres=# SELECT current_user, current_database();
postgres=# SELECT version();
postgres=# \q
```

SQL 语句通常以分号结束；反斜杠命令是 `psql` 客户端命令，不属于 SQL，不需要分号。

# 常用指令

| 功能 | 命令 |
| :--- | :--- |
| 启动服务 | `brew services start postgresql@18` |
| 停止服务 | `brew services stop postgresql@18` |
| 重启服务 | `brew services restart postgresql@18` |
| 检测服务状态 | `brew services list` 或 `pg_isready` |
| 查看服务信息 | `brew services info postgresql@18` |
| 查看日志 | `tail -f "$(brew --prefix)/var/log/postgresql@18.log"` |
| 更新 PostgreSQL 18 | `brew update && brew upgrade postgresql@18` |
| 卸载软件包 | `brew uninstall postgresql@18` |

> 次版本升级（例如 18.5 → 18.6）通常只需更新软件包并重启服务。主版本升级（例如 17 → 18）涉及数据目录格式变化，应先阅读发布说明，并使用 `pg_upgrade`、逻辑复制或备份恢复完成迁移。

# SQL 语句

SQL（Structured Query Language，结构化查询语言）用于定义数据结构、读写数据和管理权限。一条 SQL 语句通常由关键字、标识符、常量和运算符组成。下面的语句从 `users` 表中查询两个列：

```postgresql
SELECT id, name FROM users;
```

| 部分 | `SELECT` | `id, name` | `FROM` | `users` |
| :---: | :---: | :---: | :---: | :---: |
| 类型 | 关键字 | 标识符（列名） | 关键字 | 标识符（表名） |
| 作用 | 指定查询操作 | 指定要返回的列 | 指定数据来源 | 指定数据表 |

SQL 关键字通常不区分大小写，但建议统一使用大写关键字、小写表名和列名，便于阅读。字符串常量使用单引号，例如：`WHERE name = 'Alice'`；双引号主要用于引用大小写敏感或包含特殊字符的标识符。

> **提示**：更多 PostgreSQL 命令和语法可参考[中文手册 ↪](https://postgresql.ac.cn/docs/current/index.html)或[SQL 语法参考 ↪](https://www.runoob.com/postgresql/postgresql-syntax.html)。
