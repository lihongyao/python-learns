# 协程介绍

协程可以在执行过程中暂停与恢复。现代 Python 异步程序通常使用 `async def`、`await` 和标准库 `asyncio`；多个任务通常在同一线程的事件循环中协作推进。

| 方式 | 切换与内存特点 | 常见场景 |
| --- | --- | --- |
| 线程 | 操作系统调度，共享进程内存 | 同步 I/O |
| 进程 | 操作系统调度，普通内存隔离 | CPU 计算、隔离 |
| 协程 | 事件循环协作调度，共享线程内的数据 | 大量异步 I/O |

协程并发不等于多核并行。一个任务执行长时间计算或阻塞调用，会影响同一事件循环中的其他任务。

# `asyncio`

## 协程函数与协程对象

```python
import asyncio


async def double(number):
    await asyncio.sleep(0.01)
    return number * 2


async def main():
    result = await double(3)
    print(result)  # 6


if __name__ == "__main__":
    asyncio.run(main())
```

- `async def` 定义协程函数；调用后得到协程对象，不会仅因调用就执行函数体。
- `await` 获取可等待对象的结果，并在需要等待时挂起当前任务；不是每个 `await` 都必然发生任务切换。
- 原生协程对象不能反复等待；要复用结果，可保存结果或保存对应 `Task`。
- `asyncio.run()` 管理顶层事件循环和清理，通常作为程序入口。当前线程已有运行中的事件循环时不能再次调用；交互式异步环境通常直接用 `await`。

普通值和普通同步函数的返回值不一定可等待；把函数改成 `async def` 也不会自动将其中的阻塞操作变成异步操作。

## 顺序等待与并发任务

连续 `await first()`、`await second()` 通常顺序执行。要并发推进，先创建任务或使用任务组：

```python
import asyncio


async def double(number):
    await asyncio.sleep(0.01)
    return number * 2


async def main():
    first = asyncio.create_task(double(1))
    second = asyncio.create_task(double(2))
    print(await first, await second)  # 2 4


if __name__ == "__main__":
    asyncio.run(main())
```

`create_task()` 调度协程并返回 `Task`，需要在运行中的事件循环里调用。保存任务引用，并等待或获取其异常，避免任务遗漏和“异常未获取”的日志。

## 任务组 `TaskGroup`

Python 3.11 起，可用任务组管理一组相关任务的生命周期：

```python
import asyncio


async def double(number):
    await asyncio.sleep(0.01)
    return number * 2


async def main():
    async with asyncio.TaskGroup() as group:
        first = group.create_task(double(1))
        second = group.create_task(double(2))
    print(first.result(), second.result())  # 2 4


if __name__ == "__main__":
    asyncio.run(main())
```

离开任务组前会等待任务完成。某个任务因非取消异常失败时，会取消其余任务并等待清理，再通常以 `ExceptionGroup` 抛出，可用 `except*` 按类型处理；`KeyboardInterrupt`、`SystemExit` 等有特殊传播规则。

## `gather()`

`await asyncio.gather(first(), second())` 会并发调度，成功时按传入顺序返回结果列表。

| 行为 | `TaskGroup` | 默认 `gather()` |
| --- | --- | --- |
| 一个子任务失败 | 取消同组其他任务，并等待清理 | 传播首个异常，其他任务不会因此自动取消 |
| 获取结果 | 保留任务对象，退出后取结果 | 直接返回结果列表 |
| 适合场景 | 生命周期关联的一组任务 | 聚合结果或兼容已有代码 |

`gather(return_exceptions=True)` 将异常作为结果元素返回，调用方必须逐项处理；不要误当作全部成功。

# 超时与取消

## 超时

```python
import asyncio


async def main():
    try:
        async with asyncio.timeout(0.01):
            await asyncio.sleep(1)
    except TimeoutError:
        print("执行超时")


if __name__ == "__main__":
    asyncio.run(main())
```

`asyncio.timeout()` 在超时后通过取消当前任务中断等待，并在上下文外转为 `TimeoutError`。也可以使用 `await asyncio.wait_for(operation(), timeout=...)` 限制单次等待。

超时依赖协作取消，不是强制中断任意 Python 代码；清理可能让实际耗时超过指定时间。

## 协作取消

`task.cancel()` 发出取消请求；任务通常在合适的等待点收到 `asyncio.CancelledError`。

```python
import asyncio


async def worker():
    try:
        await asyncio.sleep(10)
    finally:
        print("执行清理")


async def main():
    task = asyncio.create_task(worker())
    await asyncio.sleep(0)  # 让 worker 进入等待
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("任务已取消")


if __name__ == "__main__":
    asyncio.run(main())
# 执行清理
# 任务已取消
```

`CancelledError` 继承 `BaseException`，不会被普通 `except Exception` 捕获。任务内部通常用 `finally` 清理；显式捕获取消异常后，一般应重新抛出，避免破坏任务组和超时协议。

# 避免阻塞事件循环

- 用 `await asyncio.sleep()` 代替 `time.sleep()`。
- 使用真正支持异步的网络、数据库客户端；普通文件读写并不会自动变成异步。
- 同步 I/O 可用 `await asyncio.to_thread(func, *args)` 在线程中执行。
- 大量纯 Python CPU 计算通常交给进程池；`to_thread()` 不会绕过常规 CPython 的 GIL 限制。

```python
import asyncio
from pathlib import Path


async def main():
    content = await asyncio.to_thread(Path("notes.txt").read_text, encoding="utf-8")
    print(content)


if __name__ == "__main__":
    asyncio.run(main())
```

该示例假设当前目录已有 `notes.txt`。取消等待 `to_thread()` 的任务，不会自动停止线程中已开始的同步函数。

# 并发数量与共享数据

- `asyncio.Semaphore(limit)` 配合 `async with` 限制同时进入某段操作的数量。
- `asyncio.Queue(maxsize=...)` 配合有限数量的消费者，实现任务队列和背压；大量输入不要一次创建全部任务。
- 协程在 `await` 前后仍可能发生共享状态竞争；需要时使用 `asyncio.Lock`。
- `threading.Lock` 是阻塞锁，不能替代事件循环内的异步锁。
- `asyncio` 的锁、队列等通常不支持跨线程直接使用；跨线程投递使用 `loop.call_soon_threadsafe()` 或 `run_coroutine_threadsafe()` 等接口。

`async for` 遍历异步迭代器；`async with` 管理异步资源，它们不等于自动启动并发任务。

# 生成器实现简单协程（了解）

生成器通过 `yield` 暂停，通过 `next()` 或 `send()` 恢复；它不会自己获得事件循环或自动并发执行。

生成器常用于逐步产生数据，现代异步业务通常使用原生协程。`async def` 中包含 `yield` 时定义的是异步生成器，使用 `async for` 消费，而不是把它当普通协程直接等待。

# `greenlet`（了解）

第三方库 `greenlet` 支持用户态执行上下文切换，通常由 `switch()` 显式控制。它本身不自动提供异步 I/O，也不会让普通阻塞函数自动让出线程。

# `gevent`（了解）

`gevent` 基于 greenlet 和事件循环，使用 `gevent.spawn()`、`gevent.sleep()` 等协作式接口管理任务。

`monkey.patch_all()` 可替换部分标准库阻塞操作，应在主线程、尽早且在相关导入之前调用；它会改变进程内模块行为，使用时需确认依赖兼容性。不能协作的阻塞调用和长时间计算仍会阻塞该线程。

新项目根据框架选择异步方案，不要直接混用 gevent 和 asyncio 的调度、锁或队列。
