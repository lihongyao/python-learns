# 多任务

## 并发与并行

- **并发**：多个任务在同一时间段内交替推进。
- **并行**：多个任务在同一时刻真正同时执行。

| 方式 | 内存与调度 | 常见用途 |
| --- | --- | --- |
| 线程 | 同一进程内共享内存，由操作系统调度 | 同步 I/O 密集型任务 |
| 进程 | 普通内存相互隔离，由操作系统调度 | CPU 密集型任务、隔离 |
| 协程 | 通常在单线程事件循环中协作调度 | 大量异步 I/O |

## GIL 与线程安全

常规启用 GIL 的 CPython 中，同一时刻通常只有一个线程执行 Python 字节码，因此纯 Python 计算通常不能靠线程获得多核加速。I/O 等待和部分扩展代码可以释放 GIL。

Python 3.13 起提供可禁用 GIL 的自由线程构建，但不能假定当前解释器就是该构建。是否能并行执行与构建方式、扩展库等有关。

GIL 不是业务数据的锁，不能用它保证“先检查再修改”、`counter += 1` 等复合操作的安全。

# 多线程

## 创建线程与传参

```python
from threading import Thread


def greet(name, *, message):
    print(f"{name}：{message}")


thread = Thread(
    target=greet,
    args=("张三",),
    kwargs={"message": "你好"},
    name="greet-worker",
)
thread.start()
thread.join()
# 张三：你好
```

`target` 传入函数对象，不要写成 `greet()`；单元素元组要保留逗号。线程本身不要求主入口保护块，但脚本仍可统一使用该结构。

## 生命周期

| 方法或属性 | 含义 |
| --- | --- |
| `start()` | 启动独立线程；同一个对象只能启动一次 |
| `run()` | 直接调用只在当前线程运行，不会创建新线程 |
| `join(timeout=None)` | 等待目标线程结束，始终返回 `None` |
| `is_alive()` | 判断线程是否仍在运行 |
| `name` | 调试名称，不保证唯一 |
| `daemon` | 是否为守护线程，必须在启动前设置 |

- `join(timeout)` 超时不会停止线程；调用后用 `is_alive()` 判断是否结束。
- 线程函数的返回值不会由 `join()` 返回；需要结果时使用队列或线程池。
- 子线程的未处理异常交给 `threading.excepthook()`，不会由主线程的 `join()` 重新抛出。
- 不要依赖输出顺序或 `sleep()` 协调线程。

## 守护线程与停止

只剩守护线程时，解释器可以退出，守护线程的清理工作可能无法完成。Python 没有通用、安全的强制停止线程接口；通常通过 `Event` 请求协作退出。

```python
from threading import Event, Thread

stop = Event()


def worker():
    while not stop.wait(0.1):
        # 在这里执行一轮工作
        pass


thread = Thread(target=worker)
thread.start()
try:
    print("工作线程已启动")
finally:
    stop.set()
    thread.join()
```

`Event.wait(timeout)` 在事件设置后返回 `True`，超时返回 `False`；可同时实现等待与停止信号。

# 共享数据与资源竞争

线程共享全局变量和堆对象，但各自拥有调用栈和局部名称。局部变量引用的对象仍可能被共享，不能仅凭变量定义位置判断安全性。

多个线程同时读写同一对象时，结果是否正确取决于同步协议。一次运行得到预期结果，不能证明没有竞争。

# 线程同步

## 互斥锁 `Lock`

```python
from threading import Lock, Thread

counter = 0
lock = Lock()


def increment():
    global counter
    for _ in range(1_000):
        with lock:
            counter += 1


threads = [Thread(target=increment) for _ in range(2)]
for thread in threads:
    thread.start()
for thread in threads:
    thread.join()

print(counter)  # 2000
```

所有参与读写的线程都应遵守同一把锁的约定。`with lock` 在退出时释放锁，包括发生异常的情况；`Lock` 本身不可重入。

## 常用同步工具

| 工具 | 作用 |
| --- | --- |
| `Lock` | 互斥访问临界区 |
| `RLock` | 同一线程可重复获取，必须对应释放 |
| `Event` | 发送状态或停止信号 |
| `Condition` | 在锁保护下等待条件，通常使用 `wait_for(predicate)` |
| `Semaphore`、`BoundedSemaphore` | 限制同时访问资源的数量 |
| `Barrier` | 等待一组线程到达同一阶段 |
| `threading.local()` | 保存每个线程各自的上下文数据 |

`Condition.wait()` 会暂时释放关联锁，返回前重新获取；收到通知后仍应重新检查条件。

## 死锁

不可重入锁被同一线程再次获取，或多线程按相反顺序持有多把锁，都可能死锁。

缩小临界区、统一加锁顺序，避免持锁执行耗时 I/O 或等待另一个需要该锁的线程。`with` 能保证释放已取得的锁，但不能自动防止死锁。

# 线程间通信 `queue.Queue`

优先用线程安全队列传递任务，减少手动管理共享列表：

```python
from queue import Queue
from threading import Thread

queue = Queue(maxsize=10)
results = []


def worker():
    while True:
        item = queue.get()
        try:
            if item is None:
                return
            results.append(item * 2)
        finally:
            queue.task_done()


thread = Thread(target=worker)
thread.start()
for item in range(3):
    queue.put(item)
queue.put(None)  # 单个消费者的结束标记
queue.join()
thread.join()
print(results)  # [0, 2, 4]
```

- 每次成功 `get()` 后，对应一次 `task_done()`；`join()` 等待所有已提交任务被标记完成，不是仅等待队列为空。
- 多个消费者通常需要各自的结束标记；异常处理也必须保证计数正确。
- `empty()`、`full()`、`qsize()` 不能保证下一次操作不阻塞。需要时用超时或非阻塞操作，并捕获 `queue.Empty`、`queue.Full`。

# 线程池

`ThreadPoolExecutor` 管理有限数量的工作线程，适合批量提交任务并获取结果：

```python
from concurrent.futures import ThreadPoolExecutor


def double(number):
    return number * 2


with ThreadPoolExecutor(max_workers=2) as executor:
    results = list(executor.map(double, [1, 2, 3]))

print(results)  # [2, 4, 6]
```

- `map()` 并发执行，但按输入顺序产生结果。
- `submit()` 返回 `Future`；`future.result()` 获取结果，并重新抛出任务异常。
- `as_completed()` 按任务完成顺序提供 `Future`，便于先处理已完成的结果。
- `future.result(timeout=...)` 超时只结束等待，不会停止正在运行的线程。
- `Future.cancel()` 通常只能取消尚未开始的任务；退出线程池上下文默认会等待任务完成。

不要在线程池任务内等待同一池中无法获得工作线程的另一个任务，否则也可能死锁。
