# 概述

插件架构将稳定的核心流程与可扩展功能分离，通过统一接口完成发现、加载和执行。

核心程序依赖插件契约，插件负责具体行为。普通功能拆分成函数或模块即可；需要独立扩展、部署或发现实现时，再引入插件机制。

# 目录结构

本章使用普通 Python 包组织本地插件，支持包内相对导入：

```text
plugin_system/
├── plugin_interface.py
├── plugin_loader.py
├── plugins/
│   ├── __init__.py
│   └── hello_plugin.py
└── main.py
```

`plugins/__init__.py` 保持为空。以下各代码块分别保存为注释所示文件，从主程序运行示例。

# 定义插件接口

```python
# plugin_interface.py
from abc import ABC, abstractmethod


class PluginInterface(ABC):
    @property
    @abstractmethod
    def name(self) -> str:
        """返回稳定的插件标识。"""

    @abstractmethod
    def execute(self, data: dict) -> dict:
        """处理输入并返回结果。"""
```

接口应约定输入、输出、异常和资源生命周期。这里要求插件无参数构造，用于简化示例；需要配置或外部服务时，改为明确的工厂或依赖注入。

`ABC` 提供名义上的继承约束；`typing.Protocol` 可为静态检查提供结构化接口，但都不自动验证业务数据或保证运行时行为正确。

# 动态加载插件

使用 `importlib.import_module()` 导入模块，交由正常导入机制处理包上下文与缓存：

```python
# plugin_loader.py
from importlib import import_module
from inspect import getmembers, isabstract, isclass
from pkgutil import iter_modules

from plugin_interface import PluginInterface


def load_plugins(package_name="plugins") -> dict[str, PluginInterface]:
    package = import_module(package_name)
    registry = {}
    modules = sorted(
        iter_modules(package.__path__, prefix=f"{package.__name__}."),
        key=lambda item: item.name,
    )

    for info in modules:
        if info.ispkg or info.name.rsplit(".", 1)[-1].startswith("_"):
            continue
        module = import_module(info.name)
        for _, cls in getmembers(module, isclass):
            if (
                cls.__module__ != module.__name__
                or not issubclass(cls, PluginInterface)
                or isabstract(cls)
            ):
                continue
            plugin = cls()
            name = plugin.name
            if not isinstance(name, str) or not name:
                raise ValueError("插件标识必须是非空字符串")
            if name in registry:
                raise ValueError(f"插件标识重复：{name}")
            registry[name] = plugin

    return registry
```

- 约定 `package_name` 指向可导入的包；扫描其直接子模块，跳过子包和下划线开头的内部模块，不递归扫描。
- `sorted()` 固定模块扫描顺序；它不代表完整的插件依赖排序。
- 仅实例化当前模块定义的具体插件类，避免重复收集从其他模块导入的类或抽象类。
- 示例遇到导入、构造或注册错误时直接抛出，由应用入口决定终止还是记录后隔离该插件。
- 导入模块会执行顶层代码；模块缓存与插件实例缓存不同，重复调用本函数仍会重新实例化插件。

按文件路径加载的 `spec_from_file_location()` 适合特定需求，但还需自行处理模块命名、父包、缓存和失败清理；普通包优先使用正常导入。

# 编写插件

```python
# plugins/hello_plugin.py
from plugin_interface import PluginInterface


class HelloPlugin(PluginInterface):
    @property
    def name(self) -> str:
        return "hello"

    def execute(self, data: dict) -> dict:
        message = data.get("message", "World")
        return {"result": f"Hello, {message}!"}
```

插件可以根据需求在内部使用其他模块，但不应在导入阶段就启动线程、连接服务或执行任务。

# 集成到主程序

```python
# main.py
from plugin_loader import load_plugins


def main():
    plugins = load_plugins()
    result = plugins["hello"].execute({"message": "Python"})
    print(result)  # {'result': 'Hello, Python!'}


if __name__ == "__main__":
    main()
```

主程序按稳定标识选择插件。缺少必需插件时应明确报告配置错误；执行失败时，按业务要求决定是否继续处理其他插件。

# 分发插件：入口点

插件作为第三方发行包安装时，可以用包元数据的 entry points 发现实现，避免扫描固定目录。

发行包的 `pyproject.toml` 示例：

```toml
[project.entry-points."demo.plugins"]
hello = "hello_package.plugin:HelloPlugin"
```

应用侧发现并加载：

```python
from importlib.metadata import entry_points

for entry_point in entry_points(group="demo.plugins"):
    plugin_class = entry_point.load()
    # 按前述契约校验类型、构造方式及插件标识后注册
```

`load()` 返回入口引用的对象，本例是类，不会自动创建实例。只有已安装且提供该组入口点的发行包才会被发现；同名入口与插件标识冲突仍需由应用检查。

# 插件配置和版本

配置可以指定启用状态和业务参数：

```json
{
  "hello": {
    "enabled": true,
    "options": {"message": "Python"}
  }
}
```

- 应用显式读取配置，并在加载前或构造、执行阶段使用；配置本身不会自动生效。
- 区分插件发行版本与接口协议版本，加载时检查兼容范围。
- 插件间依赖、执行优先级、超时和重试需要额外约定，不能只靠文件名排序。
- 长期运行的插件需要统一启动、停止及资源释放接口。

# 注意事项

- 动态导入会执行插件代码，只加载可信来源；进程内插件不构成安全沙箱。
- 导入失败、构造失败、执行失败分别记录上下文，避免静默吞掉异常。
- 为插件提供必要的配置和服务，减少对核心内部全局变量的依赖。
- 动态加载不等于热更新；`reload()` 不会替换已有实例及其他模块持有的旧引用。
- 需要故障或资源隔离时，考虑独立进程与明确的通信协议。
