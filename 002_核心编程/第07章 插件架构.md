# 概述

插件架构将核心功能和扩展功能分离。插件以独立模块存在，核心程序通过约定好的接口发现并调用插件，因此新增功能时通常不需要修改核心代码。

## 主要优势

- 可扩展性：新增功能可以通过新增插件实现。
- 模块化：插件可以独立开发、测试和部署。
- 解耦：核心程序只依赖插件接口，不依赖具体实现。
- 按需加载：程序启动时扫描并加载符合规则的插件。

插件本质上仍然是要执行的 Python 代码，不能把动态加载当作安全沙箱。实际项目只应加载可信来源的插件，并对插件权限进行限制。

# 目录结构

下面的示例使用一个简单的扁平插件目录，代码中的导入路径与目录结构保持一致：

```text
plugin_system/
├── plugin_interface.py  # 插件接口
├── plugin_loader.py     # 插件加载器
├── plugins/             # 插件目录
│   └── hello_plugin.py
└── main.py              # 主程序
```

# 定义插件接口

使用抽象基类规定所有插件必须提供的成员：

```python
# plugin_interface.py
from abc import ABC, abstractmethod


class PluginInterface(ABC):
    @property
    @abstractmethod
    def name(self) -> str:
        """插件名称"""
        raise NotImplementedError

    @abstractmethod
    def execute(self, data: dict) -> dict:
        """执行插件功能"""
        raise NotImplementedError
```

这里将 `name` 统一定义为只读属性，将 `execute()` 定义为方法。子类必须实现这两个成员，否则不能实例化。

如果项目使用静态类型检查，也可以使用 `typing.Protocol` 描述接口。`Protocol` 采用结构化类型，只要对象具有相应成员就可以被类型检查器接受；它不要求类显式继承接口。

# 动态加载插件

`importlib` 可以根据文件路径在运行时加载模块。下面的加载器会扫描 `plugins` 目录中的 `.py` 文件，并实例化其中实现了 `PluginInterface` 的类：

```python
# plugin_loader.py
from importlib.util import module_from_spec, spec_from_file_location
from pathlib import Path
import sys

from plugin_interface import PluginInterface


def load_plugins(plugin_dir: str | Path) -> list[PluginInterface]:
    plugins = []
    plugin_dir = Path(plugin_dir)

    for path in sorted(plugin_dir.glob("*.py")):
        if path.name == "__init__.py":
            continue

        module_name = f"plugins.{path.stem}"
        spec = spec_from_file_location(module_name, path)
        if spec is None or spec.loader is None:
            print(f"跳过无法加载的插件：{path}")
            continue

        module = module_from_spec(spec)
        sys.modules[module_name] = module
        spec.loader.exec_module(module)

        for value in vars(module).values():
            if (
                isinstance(value, type)
                and issubclass(value, PluginInterface)
                and value is not PluginInterface
            ):
                plugins.append(value())

    return plugins
```

说明：

- 使用 `sorted()` 让插件加载顺序稳定。
- 将模块放入 `sys.modules`，有助于模块内部使用正常的导入机制。
- 插件类应提供无参数构造方法；需要配置时，可以在加载器中显式传入配置。
- 这段代码只负责本次运行时的扫描和加载，不包含自动重载功能。

# 编写插件

在 `plugins` 目录下创建 `hello_plugin.py`：

```python
# plugins/hello_plugin.py
from plugin_interface import PluginInterface


class HelloPlugin(PluginInterface):
    @property
    def name(self) -> str:
        return "HelloPlugin"

    def execute(self, data: dict) -> dict:
        message = data.get("message", "World")
        return {"result": f"Hello, {message}!"}
```

加载器实例化 `HelloPlugin` 后，主程序可以通过统一的 `name` 和 `execute()` 与它交互，而不需要知道插件内部的实现细节。

# 集成到主程序

```python
# main.py
from plugin_loader import load_plugins


def main():
    plugins = load_plugins("plugins")
    if not plugins:
        print("没有找到可用插件")
        return

    print("可用插件：")
    for index, plugin in enumerate(plugins, start=1):
        print(f"{index}. {plugin.name}")

    try:
        choice = int(input("请选择插件编号：")) - 1
        if choice < 0 or choice >= len(plugins):
            raise IndexError
        plugin = plugins[choice]
    except (ValueError, IndexError):
        print("选择无效")
        return

    message = input("请输入消息内容：")
    result = plugin.execute({"message": message})
    print("插件执行结果：", result)


if __name__ == "__main__":
    main()
```

主程序只依赖 `PluginInterface` 约定的接口，因此新增插件时不需要修改主程序的分支逻辑。

# 插件配置和版本

插件较多时，可以使用 JSON 等文件保存插件元数据，例如名称、版本和是否启用：

```json
[
  {
    "name": "HelloPlugin",
    "version": "1.0.0",
    "enabled": true
  }
]
```

加载插件时可以先读取配置，再根据 `enabled`、版本和依赖关系决定是否加载。配置文件本身不会自动完成版本兼容检查，检查逻辑需要由应用程序实现。

# 注意事项

- 接口应尽量小而稳定，避免插件依赖核心程序的内部实现。
- 动态加载和插件执行过程应记录日志，并妥善处理单个插件的异常。
- 插件通常可以执行与主程序相同的系统操作，必须只加载可信插件。
- 使用持久化配置时，应为插件定义稳定的标识和版本规则。
- “动态加载”不等于“热更新”；热更新还需要处理旧模块、运行中任务和资源释放等问题。
