# 进程介绍

进程拥有独立地址空间；普通 Python 对象的修改不会自动同步到其他进程。进程可以包含多个线程，创建与通信开销通常高于线程。

多进程适合 CPU 密集型计算和隔离任务，但序列化、进程启动及结果传输可能抵消收益，不是任务越多越快。

# 多进程

## 创建进程

以下多进程示例应保存为独立 `.py` 文件运行。使用 `spawn` 时，目标函数放在模块顶层，启动逻辑放在主入口保护块内：

```python
from multiprocessing import get_context


def greet(name):
    print(f"你好，{name}")


if __name__ == "__main__":
    ctx = get_context("spawn")
    process = ctx.Process(target=greet, args=("张三",))
    process.start()
    process.join()
    print(process.exitcode)  # 0
```

`target` 传入函数对象，`args`、`kwargs` 用于传参。子进程会导入主模块，保护块能避免再次创建进程；不要把启动操作放在模块顶层。

## 生命周期

| 方法或属性 | 作用 |
| --- | --- |
| `start()` | 启动，单个进程对象只能启动一次 |
| `join(timeout=None)` | 等待结束，返回 `None` |
| `is_alive()` | 检查进程是否仍存活 |
| `pid`、`name` | 进程编号、名称 |
| `exitcode` | 未结束为 `None`，正常退出为 `0`，未捕获异常通常为 `1` |
| `terminate()`、`kill()` | 强制终止，不保证执行清理逻辑 |
| `close()` | 释放已结束的进程对象所持有的资源 |

`join()` 不会重新抛出子进程异常；应检查 `exitcode` 或通过通信通道传递结果。超时后仍需检查 `is_alive()`，超时不会自动终止进程。

守护进程在父进程退出时可能被终止，不能创建子进程；这里的 `daemon` 不是操作系统服务的含义。

## 启动方式

| 方式 | 主要行为与限制 |
| --- | --- |
| `spawn` | 启动新解释器并导入代码；参数通常需要可 pickle 序列化 |
| `fork` | 复制当前进程状态；多线程进程中存在风险，仅部分 POSIX 平台支持 |
| `forkserver` | 由专门的服务进程派生工作进程，仅支持它的平台可用 |

- Windows、macOS 默认使用 `spawn`。
- Python 3.14 起，支持 `forkserver` 的其他 POSIX 平台默认使用它；`fork` 不再是任何平台的默认启动方式。
- 用 `get_context()` 显式选择上下文，相关进程、队列、锁尽量由同一上下文创建，不要混用不兼容对象。
- `set_start_method()` 修改全局启动方式，通常只应在主入口调用一次；库代码优先允许调用方传入上下文。

`spawn`、`forkserver` 通常要求目标函数可从模块导入；局部函数、`lambda` 和交互式定义的函数不适合直接作为工作目标。

# 进程间通信

## 普通变量不共享

即使通过参数把列表传给子进程，子进程修改它也不会自动修改父进程中的列表。`fork` 下看到初始数据也不等于后续修改共享。

| 工具 | 用途 |
| --- | --- |
| `Queue` | 多生产者、多消费者消息传递，数据经 pickle 序列化 |
| `Pipe` | 通过连接对象收发消息 |
| `Value`、`Array` | 共享简单数值和数组 |
| `shared_memory` | 显式共享内存块，减少大数据复制 |
| `Manager` | 通过管理进程和代理访问共享对象，方便但有通信开销 |

进程锁只负责同步，不能让普通列表自动变成共享列表。`Value` 等工具的复合更新也需要正确加锁。

## 使用队列通信

```python
from multiprocessing import get_context


def producer(queue):
    for name in ["张三", "李四"]:
        queue.put(name)
    queue.put(None)


if __name__ == "__main__":
    ctx = get_context("spawn")
    queue = ctx.Queue(maxsize=10)
    process = ctx.Process(target=producer, args=(queue,))
    process.start()

    while True:
        item = queue.get(timeout=5)
        if item is None:
            break
        print(item)

    process.join()
    queue.close()
    queue.join_thread()
# 张三
# 李四
```

- 对象在队列中经过序列化，读取后不能依赖 `is` 身份关系。结束标记应使用可稳定识别的值，例如协议约定的 `None`。
- 队列可能由后台线程刷新；大量数据未被读取前就 `join()` 生产者，可能造成死锁。
- `empty()`、`full()`、`qsize()` 结果不可靠，部分平台甚至不支持 `qsize()`；不要用它们判断任务是否全部结束。
- 超时的 `get()`、`put()` 分别抛出标准库 `queue.Empty`、`queue.Full`，不是 `multiprocessing` 中的同名异常。
- 多生产者之间的消息顺序不保证；单个生产者放入的消息保持相对顺序。

使用结束标记时还需约定生产者、消费者数量；一个生产者发送的标记不能代表其他生产者已经结束。

# 进程池

## `ProcessPoolExecutor`

批量计算优先考虑与线程池接口一致的 `ProcessPoolExecutor`：

```python
from concurrent.futures import ProcessPoolExecutor
from multiprocessing import get_context


def square(number):
    return number * number


if __name__ == "__main__":
    with ProcessPoolExecutor(max_workers=2, mp_context=get_context("spawn")) as executor:
        results = list(executor.map(square, [1, 2, 3]))
    print(results)  # [1, 4, 9]
```

- `map()` 按输入顺序产出结果，不代表串行执行；`chunksize` 可调节进程池分块提交的粒度。
- `submit()` 返回 `Future`；`result()` 读取结果或重新抛出任务异常。
- 函数、参数和结果都需要满足序列化要求；不要把无法序列化的连接或打开的文件随意传入。
- 等待结果超时、取消尚未启动的任务和终止进程是不同操作。
- 进程池中的任务不要调用该池的 `Executor` 或 `Future` 方法，避免死锁。

## `multiprocessing.Pool`

已有代码也常用 `Pool`：

```python
from multiprocessing import get_context


def double(number):
    return number * 2


if __name__ == "__main__":
    with get_context("spawn").Pool(processes=2) as pool:
        print(pool.map(double, [1, 2, 3]))  # [2, 4, 6]
```

| 方法 | 行为 |
| --- | --- |
| `apply()` | 提交一个任务并等待结果 |
| `apply_async()` | 返回 `AsyncResult`，用 `get()` 取结果或异常 |
| `map()` | 等待批量结果，按输入顺序返回列表 |
| `imap()`、`imap_unordered()` | 逐步获取结果，后者不保证输入顺序 |
| `close()` | 不再接收新任务 |
| `terminate()` | 立即终止工作进程，未完成任务可能丢失 |
| `join()` | 等待工作进程结束，先调用 `close()` 或 `terminate()` |

`Pool` 上下文退出会调用 `terminate()`，并非自动等待所有异步提交完成。使用 `apply_async()` 时应在退出前获取结果或显式安排完成流程；上例的 `map()` 已等待任务完成。

# 执行外部程序

运行命令行工具应使用 `subprocess`，不必为了调用外部程序再手动创建 `multiprocessing.Process`：

```python
import subprocess
import sys

result = subprocess.run(
    [sys.executable, "-c", "print(1 + 2)"],
    check=True,
    capture_output=True,
    text=True,
    timeout=5,
)
print(result.stdout.strip())  # 3
```

优先使用参数列表和默认的 `shell=False`。`check=True` 在非零退出时抛出 `CalledProcessError`；`run(timeout=...)` 超时会终止并等待子进程，再抛出 `TimeoutExpired`。
